# R20 · Publish as keel-sdlc, runnable with one command

## Goal

Remove SQLite, then publish: `npx keel-sdlc [path]` starts a pre-built Keel on a folder, with nothing to clone, install or build; the command is `keel`.

## Scenarios that prove it

- CI job `package-smoke` (macOS, Linux, Windows): pack, install into an empty folder, run `keel --version`, `keel --dry-run`, and start `keel --no-open` on a new folder until the first page answers.
- Existing acceptance scenarios still pass against the standalone server, with the design-decisions storage example renamed (no SQLite).
- A unit test fails if any dependency in the production tree has native code (`binding.gyp`, `.node` files).

## Data

- `package.json`: `name: keel-sdlc`, `private: false`, `bin: { keel: bin/keel.mjs }`, `files: ["bin/", "dist/", ".next/standalone/", ".next/static/", "seed/", "public/", "README.md", "LICENSE"]`, `engines.node: ">=20"`, `repository`, `keywords`, `license`.
- Scripts: `build` (next build, then `scripts/copy-standalone.mjs` copies `.next/static` and `public` into `.next/standalone`), `build:cli` (compile `src/cli.ts`, now only `import`, to `dist/cli.mjs`), `prepack` (build and build:cli), `smoke` (`scripts/smoke.mjs`).

## Files that are likely to change

- Remove: `src/lib/store/db.ts`, `src/lib/store/reindex.ts` (move `versionFromCommit` to `src/lib/versions/`), `src/lib/settings/migrate.ts` and its test, the `Index` type and every `store.index` call (store, documents, versions, seed, tests, `test-store.ts`, `server-store.ts`), the `reindex` command in `src/cli.ts`, `better-sqlite3` and `@types/better-sqlite3` in `package.json`.
- Rename the storage example in `src/lib/providers/fake.ts`, `src/app/dev/ui/page.tsx`, `features/design-decisions.feature` and its steps to "Markdown files in git" / "A single database file".
- `src/components/WhatKeelCreates.tsx` and the handoff list: `.keel/cache/` holds the run lock only; `features/steps/project-folder.steps.ts` checks `.keel/cache/run.json` is ignored instead of `index.db`.
- `package.json`, `next.config.mjs` (`output: 'standalone'`, no `serverExternalPackages`, `outputFileTracingIncludes` for `seed/**`).
- `bin/keel.mjs`: find the install folder from `import.meta.url`; prefer `.next/standalone/server.js` (env `HOSTNAME`, `PORT`, `KEEL_PROJECT_DIR`, `KEEL_SEED`); fall back to `next dev` in a clone; `--version`; the `import` subcommand calling `dist/cli.mjs`.
- `src/lib/templates/library.ts` (and any other `process.cwd()` used to find Keel's own files): resolve from the install folder (`KEEL_HOME_DIR` set by the CLI), keep `KEEL_SEED`.
- New `scripts/copy-standalone.mjs`, `scripts/smoke.mjs`.
- `.github/workflows/ci.yml`: add `package-smoke` on a matrix of `ubuntu-latest`, `macos-latest`, `windows-latest`.
- New `.github/workflows/release.yml`: on tag `v*`, verify, build, pack, smoke, `npm publish --provenance --access public` with `NPM_TOKEN`; never on other events.
- `README.md` (quick start), `docs/user-guide.md` (Before you start), new `LICENSE` if missing (ask the owner which licence).
