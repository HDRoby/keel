# R7 · Handoff writes into the folder

## Goal

Handoff writes the agent files into the project folder. The documents are already there.

## Scenarios that prove it

- `features/handoff.feature` › Handoff writes the agent files into the project folder
- `features/handoff.feature` › Handoff does not overwrite a file Keel did not write

## Files that are likely to change

- `src/lib/handoff/scaffold.ts`: return the list of files to write (AGENTS.md, CLAUDE.md, REVIEW.md, `.claude/agents/*`, `.claude/skills/*`, `features/*.feature`, `.github/workflows/ci.yml`). Documents in `docs/` and `tasks/` are no longer copied: they are already in place.
- New `src/lib/handoff/write.ts`: compare each file with the folder.
  - **New**, **Changed (written by Keel before)**, **Unchanged**, or **Conflict (exists and Keel did not write it)**.
  - Writes New and Changed, skips Unchanged, and for Conflict asks: Keep mine, Use Keel's, or Write as `<name>.keel.md` next to it.
  - Commits the written files as one Keel commit "Keel: Handoff for plan v<N>".
- Track which files Keel wrote, with their hash, in `.keel/config.yml` `handoff.files`.
- Handoff page: the file list with these states, "Write to folder", and "Download as zip" (the existing zip, kept).
- The secret scan test runs on the written files.

## As built

- `buildHandoff` (`scaffold.ts`) still builds the whole package; it is what "Download as zip" serves. The folder write takes only the agent files from it.
- New `src/lib/handoff/write.ts`:
  - `planHandoff(store)` lists what Handoff writes into the folder: AGENTS.md, CLAUDE.md, REVIEW.md, `.claude/agents/*`, `.claude/skills/*`, `features/*.feature` with the failing stubs in `features/steps/`, `.github/workflows/ci.yml`, `docs/traceability.json`, and `docs/roadmap.md` when the project has none. Documents in `docs/` and `tasks/` and the mocks are not copied, because they are already in place. The minimal setup (package.json, tsconfig.json, playwright.config.ts, .gitignore, README.md) is written only when the folder has none, and is shown as "Yours, kept" otherwise, never as a conflict.
  - Each file gets a state: **New**, **Changed** (Keel wrote it and nobody changed it since), **Unchanged**, or **Conflict** (in the folder, different, and not as Keel left it).
  - `writeHandoff(store, choices)` writes New and Changed files. A Conflict is left alone unless the user chooses Keep mine, Use Keel's, or Write as `<name>.keel.<ext>` next to it (`AGENTS.keel.md`, `ci.keel.yml`). It commits the written files and `config.yml` as one Keel commit "Keel: Handoff for plan v<N>", and makes no commit when nothing is new. It refuses during a merge or rebase (R5).
  - `config.yml` `handoff.files` holds the sha256 of every file Keel wrote. That is how Changed is told apart from Conflict.
  - The secret scan runs on the files about to be written, against the patterns and the keys stored in Settings, as well as on the whole package in `buildHandoff`. When it finds something, nothing is written.
- Handoff page: "Handoff into this folder" with a table of the files and their states, the three choices on each conflict (Keep mine selected), "Write to folder", and "Download as zip". A notice says how many files were written in one Keel commit and how many conflicts were left as they are. The push card stays until R8.
- Tests: `write.test.ts` covers the states, the `.keel` names, one Keel commit with only the handoff files and `config.yml` (a stray `notes.txt` stays out), no commit when nothing is new, each conflict choice, a file Keel wrote becoming Unchanged, the user's own `package.json` kept, and a stored key stopping the write.
- Both handoff scenarios pass: the folder gets AGENTS.md, REVIEW.md and the agent kit, every scenario has a failing stub, no file in the folder (including `.git`) has the stored key or a key pattern, and the last commit is the Keel handoff commit. An AGENTS.md committed by the user shows as a conflict and stays unchanged after "Write to folder".
- Fixed while here: `secrets.test.ts` failed about 1 run in 64 because its "tampered" ciphertext could equal the original.
