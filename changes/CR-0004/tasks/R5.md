# R5 · Documents written and committed in the folder

## Goal

Write documents to `docs/`, `tasks/` and `features/` of the project folder and commit only Keel's own paths.

## Scenarios that prove it

- `features/project-folder.feature` › Keel commits only its own files

## Files that are likely to change

- `src/lib/store/git.ts`: `commitFiles(root, paths, message)` uses a pathspec (`git commit --only -- <paths>` after `git add -- <paths>`) so the user's staged files stay staged and out of Keel's commit. Author `Keel <keel@localhost>`, subject prefixed `Keel: `.
- `src/lib/store/documents.ts`: paths from `config.yml` `paths`.

## Rules

- Refuse to commit during a merge, rebase or cherry-pick (`.git/MERGE_HEAD`, `rebase-merge`, `rebase-apply`, `CHERRY_PICK_HEAD`). Show "Finish the merge in git, then try again" and keep the change unsaved.
- Before writing a document, compare the working copy with Keel's last version. If it differs (someone edited it), do not overwrite: show it in read-back first.
- Commit to the current branch. A detached HEAD is refused with a message.
- `config.yml` commit mode `auto` (default) or `off`. With `off`, Keel writes files but does not commit; versions then come from Keel's own record in `.keel/` history. Implement `auto` only in this task; `off` can be a follow-up if it adds risk.
