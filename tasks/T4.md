# T4 · Brainstorm service: template-driven questions and styles

## Goal

Run the brainstorm chat. The intent template decides which sections to fill; the brainstorm style (a skill file from seed/styles) decides how to ask. Track which sections are captured.

## Scenarios that prove it

- `features/brainstorm.feature` › The assistant asks about the next missing required section (@REQ-001)
- `features/brainstorm-styles.feature` › The chosen style is recorded with the intent (@REQ-011)

## Files that are likely to change

- `src/lib/brainstorm/session.ts`
- `src/lib/brainstorm/sections.ts`
- `src/lib/brainstorm/styles.ts`
- `src/app/projects/[id]/explore/page.tsx`

## Notes

- Template and style are chosen on Start and fixed during the brainstorm; they can be changed in Project setup.
- Intent unlocks when every required section is captured.
- Chat UI: user messages in a light bubble on the right, assistant replies as plain text; no avatars or timestamps.
- As built (owner decisions, 2026-11-20):
  - The seed template "Standard intent v3" names its second section **Desired outcome** (was "Proposed outcome"), to match `brainstorm.feature`. Keel's own `docs/intent.md` is unchanged. Workspaces seeded before this change keep their old copy.
  - Each section gets one question, then one follow-up probe in the chosen style. Both answers go into the section. Then the next missing required section, then the optional ones. A section counts as captured after its first answer. Draft intent.md is enabled when every required section is captured.
- The brainstorm lives in `brainstorm.md` at the project root: state in front matter, a readable transcript in the body, one commit per turn. The model only words the questions; which section comes next is decided by Keel, so it works the same with any provider. If no model is reachable, Keel asks a plain question from the template guidance and says so.
- Screens: Start (`/start`), Explore (`/projects/[id]/explore`, streamed replies via `POST /api/projects/[id]/brainstorm`), Project setup (`/projects/[id]/setup`), and the Projects list.
- Styles are copied from `seed/styles` to `KEEL_HOME/styles/<name>@<version>.md` on first run, like templates. The Brainstorm styles screen (`/styles`, `/styles/[id]`) edits a style as a new version; started brainstorms keep their version until changed in Project setup.
- Brainstorm turns are squashed: consecutive brainstorm saves are folded into one commit ("Brainstorm: captured …"). Any other commit, such as an intent version, starts a new one.
- The brainstorm continues after intent.md is drafted. While the intent is a draft, new answers can be saved as its next version ("Update intent.md", reason "Brainstorm: add answers for …"). Once it is approved or later, brainstorm answers no longer change it.
- Fix after the T5 verification: an update used to rebuild the whole intent from the answers, which undid hand edits. Now the brainstorm records how many answers per section intent.md already has (`in_intent`). An update only adds newer answers at the end of their sections; everything else in intent.md stays as edited. Hand edits alone no longer show as new answers. Chat bubbles keep line breaks.
- Test setup: scenarios share the dev server's workspace, so `playwright.config.ts` now runs them one at a time (`workers: 1`) and empties that workspace when the BDD server starts.
