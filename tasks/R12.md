# R12 · Design as decisions

## Goal

The Spec's Design tab lists decision topics with options proposed by the assistant. Each choice is a decision record.

## Scenarios that prove it

- `features/design-decisions.feature` (all scenarios)

## Data

- Stored with the spec (front matter `decisions:` or `.keel/spec/decisions.json`, whichever fits the store best):
  `{ topic, title, origin: 'template' | 'assistant', reason_added?, options: [{ id, name, summary, pro, con, serves: [REQ], fit: { kind: 'follows' | 'breaks' | 'conflicts' | 'adds-concern', text }, recommended }], chosen?, own?, reason?, record? }`.
- Decision records in `docs/decisions/NNNN-<slug>.md` from the decision-record template, with "Alternatives considered" listing the options not chosen.

## Files that are likely to change

- Spec template (`seed/templates/spec-standard.md`): a `decision_topics` list (form, stack, storage, model access, testing). New template version.
- `src/lib/generate/spec.ts`: replace Design prose with `proposeDecisions(intent, standards, repoFacts, template)`. One model call returns topics and options, validated with zod. Extra topics must name the requirement that needs them.
- New `src/lib/repo/facts.ts`: read facts from the folder (package.json dependencies, lock files, language files) so "Keep current" can be offered. No network.
- New `src/lib/decisions/records.ts`: `decide(topic, option, reason)` writes or rewrites the record while the spec is a draft; after approval it creates a change request and a superseding record. Uses the existing ADR numbering.
- `src/lib/decisions/own.ts`: review a user-written option against requirements and standards (model call), returning a fit line.
- `src/lib/generate/approach.ts`: assemble Approach and Components from the chosen options; recompute feasibility notes and flagged concerns that depend on them.
- `src/lib/gates/*`: plan gate adds "every topic decided".
- `src/app/(project)/spec/page.tsx`: Design tab as in the mockup: progress line, a card per topic (options, own option, reason, Decide, Change, Cancel), Approach summary, Standards applied.

## Notes

- Options must be concrete and comparable; no more than three proposed per topic.
- The assistant never changes a decision on its own. A new requirement may make it add a comment on a topic ("REQ-014 needs real-time updates; your read-back choice polls every minute").
