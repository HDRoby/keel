# R1 · Project folder and .keel store

## Goal

Replace the workspace of many projects with one project folder and its `.keel/` (ADR-0009, ADR-0010).

## Scenarios that prove it

- `features/project-folder.feature` › Initialising creates the .keel folder
- `features/project-folder.feature` › A folder that is not a git repository becomes one

## Files that are likely to change

- `src/lib/store/workspace.ts`: remove `keelHome`, `projectDir`, `listProjectSlugs`, `SLUG`, `createProject`. Add:
  - `projectRoot(env)`: from `KEEL_PROJECT_DIR`, absolute, must exist.
  - `keelDir(root)`, `isInitialised(root)`.
  - `initialiseProject(store, input)`: `git init` if needed, writes `.keel/config.yml`, `.keel/.gitignore` (`cache/`), seeds libraries, commits "Keel: Initialise project".
  - `readProject(root)` from `config.yml` (same zod schema plus `description`, `templates`, `style`, `paths`).
  - `reserveRequirementIds` and `setProjectStandards` keep their behaviour on `config.yml`.
- `src/lib/store/db.ts`: index at `.keel/cache/index.db`.
- `src/lib/store/server-store.ts`: store keyed by project root, not home.
- `src/lib/store/reindex.ts`: one project.
- `src/lib/seed.ts`: seed into `.keel/`.
- `src/lib/templates/library.ts`, `src/lib/skill-files.ts`, `src/lib/handoff/scaffold.ts`, `src/lib/gates/approvals.ts`, `src/lib/generate/*`: read libraries from `keelDir(root)` instead of `store.home`.
- The `Store` type: `home` becomes `root`.

## Notes

- Keep functions taking the root as a parameter so tests use a temporary folder.
- `slug` disappears from function signatures. Use the project id where a label is needed.
- Tests: rewrite `workspace.test.ts` around a temporary git repository.
