# R15 · Opening a folder: four cases

## Goal

Scan the folder, recognise the case, and offer the right start; for existing projects, draft a baseline and respect the existing AI setup.

## Scenarios that prove it

- `features/opening-a-folder.feature` (all scenarios)

## Files that are likely to change

- New `src/lib/repo/scan.ts` (extends `facts.ts` from R12): `scanFolder(root)` returns `{ git: { repo, commits, contributors }, stack, docs, tests, agentFiles, specTools, usedFolders, keel }` and `kase: 'new' | 'keel' | 'existing' | 'existing-ai'`. Reads file names, manifests and agent files only. Must finish under 1 second on a 10,000-file repo (skip `node_modules`, `.git`, build folders, respect `.gitignore`).
- New `src/lib/keel/checks.ts`: for case 2, `checkKeelFolder(root)` returns config upgrades, pending read-back count, and missing documents or library versions.
- New `src/lib/config/migrate.ts`: `formatVersion` in `.keel/config.yml`; one function per upgrade; applied in one Keel commit after the user agrees.
- New `src/lib/baseline/draft.ts`: `draftBaseline(root, files, template)` sends only the chosen files (with a size cap) to the model and returns section suggestions, "as built" requirements and "Keep current" decisions, validated with zod. Without consent, it returns stack-only decisions and empty sections.
- New `src/lib/baseline/import-specs.ts`: parse Spec Kit `specs/*/spec.md`, Kiro specs and plain PRDs into requirement suggestions with `alias` set to the original ID.
- New `src/lib/standards/from-agent-files.ts`: extract short, checkable rules from `AGENTS.md`, `CLAUDE.md` and Cursor rules (model call on those files only, with consent) and write the accepted ones to `.keel/standards/project-conventions/SKILL.md`.
- `src/lib/handoff/write.ts` (R7): AGENTS.md merge inside `<!-- keel:start -->` and `<!-- keel:end -->` markers, created if missing; CLAUDE.md pointer line if missing; never rewrite text outside the markers.
- Initialise page: as in `docs/mocks/source/Start.dc.html` (four cases; remove the mockup's case switcher).
- Requirements and decisions created by the baseline carry `origin: baseline`; the intent shows "Baseline v1" until the first change request.

## As built

- **Scan:** `src/lib/repo/scan.ts`. `scanFolder(root)` reads file names, manifests and agent files only, skipping `node_modules`, `.git`, build and cache folders, and stopping at 10,000 files. It returns git facts, the stack, code files, docs, tests, agent files, spec tools, folders already in use, the files the assistant could read for a baseline (with sizes), and the case: `new`, `keel`, `existing` or `existing-ai`. Nothing is written and nothing is sent.
- **Opening a Keel folder:** `/` runs `checkKeelFolder` (`src/lib/keel/checks.ts`) before the current stage. When something needs attention it shows a page with Continue to <stage>. Otherwise it goes straight to the stage, as before. The checks:
  - an older config: `src/lib/config/migrate.ts`. A config without `format` is format 1; this Keel writes format 2 (and `mock_gate`). The page lists what the upgrade changes, and "Upgrade in one Keel commit" applies it;
  - changes waiting in Read-back;
  - templates, styles or standards named in the config but missing (a repair notice).
- **Initialise:**
  - "What Keel found" with the case and the facts.
  - For an existing project:
    - How to start: "Record what exists, then plan the next change" (recommended) or "Treat the next feature as the project".
    - "Let the assistant read these files": a table with sizes and a total, a checkbox per file, and "Send no file".
  - For the AI-setup case, also your agent files with what Keel will do, and the rules found in them as checkboxes.
  - The primary button follows the path: "Initialise and draft the baseline" or "Initialise and start brainstorm".
- **Baseline:** `src/lib/baseline/draft.ts`. One model call with only the files the user ticked (each capped at 100 KB, 200 KB in all); nothing is sent when none are ticked. The suggestions go into Explore:
  - empty text sections get suggested text;
  - requirements become suggested rows marked "(as built)";
  - Spec Kit and Kiro requirements are added with their original IDs (`import-specs.ts`).

  `.keel/baseline.json` records the stack and what was sent. When the spec is generated, "Keep current: <stack>" is decided for Language and framework, with a record saying it was recorded from the existing code (`baseline/decisions.ts`).
- **Rules:** `src/lib/standards/from-agent-files.ts` finds short imperative lines in AGENTS.md, CLAUDE.md, GEMINI.md, Cursor, Windsurf and Copilot rules, locally (no model call: the files are read, not sent). The accepted rules become `.keel/standards/project-conventions/SKILL.md` and `project-conventions@1` joins the project's standards, all in the Initialise commit. The skill-file library now reads that folder form as well as `<name>@<version>.md`.
- **Handoff (owner decision):** AGENTS.md and CLAUDE.md that were in the folder at Initialise are recorded as `agent_files_at_start` in the config:
  - AGENTS.md gets Keel's instructions between `<!-- keel:start -->` and `<!-- keel:end -->`; the text outside the markers never changes.
  - CLAUDE.md gets one pointer line if it does not mention AGENTS.md.
  - An AGENTS.md added later stays a conflict, as in R7.
- **Fixtures:** `features/fixtures/folders/{new,keel,existing,existing-ai}`; each is scanned as its case with nothing written.
- **Not built:**
  - Proposing `keel/docs`, `keel/tasks` and `keel/features` when those folders mean something else. The code writes `docs/`, `tasks/` and `features/` in many places, so Keel shows a notice instead.
  - "Baseline v1" on the intent until the first change request.
  - Rules are found by pattern, not by a model call.
- **Tests:** `src/lib/repo/opening.test.ts` (7) and `features/steps/opening-a-folder.steps.ts` (5 scenarios).
