# R4 · Routes and screens without Projects

## Goal

One project, so no project id in the URL and no Projects page. Screens follow the clickable mockup (CR-0004 version).

## Scenarios that prove it

- `features/project-folder.feature` › Opening a folder without .keel offers to initialise it
- `features/stage-gating.feature` (unchanged scenarios, new URLs)

## Routes

| Before | After |
| --- | --- |
| `/` (Projects list) | `/`: Initialise when the folder has no `.keel/`, otherwise redirect to the current stage |
| `/start` | removed; its form is the Initialise screen at `/` |
| `/projects/[id]/setup` | `/setup` |
| `/projects/[id]/explore`, `intent`, `spec`, `plan`, `handoff`, `trace`, `versions` | `/explore`, `/intent`, `/spec`, `/plan`, `/handoff`, `/trace`, `/versions` |
| `/api/projects/[id]/*` | `/api/*` (brainstorm, handoff, mocks) |
| `/templates`, `/styles`, `/settings` | same paths |

## Files that are likely to change

- Move `src/app/projects/[id]/*` to a route group `src/app/(project)/`. Its layout redirects to `/` when the folder is not initialised.
- Delete `src/app/(workspace)/page.tsx` and `start/` (ask the owner before deleting, or move to `_removed/` if deletion is not allowed).
- `src/app/projects/actions.ts`: drop `createProject` and `deleteProject`; add `initialiseProject`.
- `src/components/Shell`: header shows the project title and its folder path in grey. Nav groups:
  - **Project:** Project setup, Explore, Intent, Spec, Plan, Handoff, Roadmap, Changes.
  - **Library:** Templates, Brainstorm styles, Standards.
  - **Settings**, at the bottom.
- `src/components/StageBar`: no `project` prop; hrefs are top-level.
- Templates, Styles and Standards pages: subtitle "Stored in .keel/templates" (or styles, standards).
- Settings page: two cards. **This project** (`.keel/config.yml`: paths, commit mode, read-back interval). **You, on this computer** (user config folder: providers, keys, model per task, author).
- Not-found page: link to `/`.

## Initialise screen

- Title "Initialise this folder", the folder path, and a note "Keel will create .keel/ here. Nothing else changes until you approve documents."
- Fields: title, description, author (prefilled from git), templates per kind (intent, spec, plan), brainstorm style, standards. The same cards as the old Start page.
- If the folder is not a git repository: "This folder is not a git repository. Keel will run git init."
- If `docs/intent.md` with a Keel header exists: "Keel documents found" with Adopt (R9).
- After the folder card, a "What Keel creates in this folder" section:
  - One short note per choice (the idea, intent template and style, document templates, agent kit, standards), each with how many files it produces.
  - A table of every path Keel will create, with what it is for and when: Now (Initialise), As you approve, or At handoff.
  - Paths that depend on a selection (standards, agent kit, REVIEW.md, mocks) are shown in a different colour, with a colour key. They can be zero to many files.
  - Each folder can be opened and closed, and all folders start closed. A closed folder shows how many files it holds. "Expand all" and "Collapse all" sit in the table header. The table is a reference, not a step.
  - The table updates as the user changes the choices below. A line under it says how many files Initialise writes, all inside `.keel/`.
- Button "Initialise and start brainstorm" goes to `/explore`.
