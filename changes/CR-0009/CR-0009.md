# CR-0009: Clickable mock made elsewhere from the spec, attached as a versioned mock set

## Why

For software with a UI, a clickable mock catches design problems before any code. Keel does not generate mocks (decided 2026-11-20), but it can hand a good prompt to a model that does, take the exported screens back, and keep them tied to the spec version they were made from. Out-of-date mock images caused confusion during the owner's own review.

## What changes

1. **The Spec's "Mock references" tab becomes "Clickable mock".**
2. **Prompt pack.** "Make a clickable mock elsewhere" builds a prompt from the spec:
   - the problem, first user, Form and stack decisions;
   - the requirements with their IDs;
   - the screens Keel infers from the requirements and scenarios (number, name, what it shows, REQ IDs), viewable as a list;
   - the UI standard (`docs/ui-guide.md` or the chosen design system) and the locked and empty states the scenarios describe;
   - rules: realistic sample data, one screen per artboard, linked screens;
   - export naming: `spec-v<N> · <number> · <screen> · <REQ IDs>.png`, and the HTML source with the same name.
   Actions: **Copy prompt** and **Download** `keel-mock-prompt-spec-v<N>.md`. Model-agnostic.
3. **Attach the result.** Drop PNG files and, ideally, their HTML sources, or paste a link to the live prototype. Keel matches each file to a screen and its requirements from the file name, flags files it cannot match ("Check", "Choose a screen"), and the user confirms. Saved as a **mock set** in `docs/mocks/set-<n>/` with a README: screen, requirements, spec version, export date, source file.
4. **Versioned.** Each mock set records the spec version it was made from. When the spec gets a new version, the set shows "Out of date · made from spec v8, the spec is v9", like other stale documents. A new set replaces the current one; older sets stay in history.
5. **Gate setting.** Project setting "Clickable mock before the plan" (Settings, This project): **Recommended** (default: Generate plan warns if the set is missing or out of date), **Required** (Generate plan stays locked), or **Off**. It applies only when the Form decision has a UI.
6. **Used downstream.**
   - Plan: tasks that build a screen link to it.
   - Handoff: `docs/mocks/` is written to the folder and AGENTS.md points to the current set, HTML sources first.
   - The UI checklist (CR-0008) can be generated from the current set's screens.
7. **Other references** (links, images, PDF) stay available under the mock set, as before.
