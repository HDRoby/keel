# T9 · Read-back from the repository

## Goal

Poll pushed repositories for agent commits that change docs/ or tasks/, show them as pending, and accept them as new versions or dismiss them.

## Scenarios that prove it

- `features/read-back.feature` › An agent change to the plan shows up for review (@REQ-007)

## Files that are likely to change

- `src/lib/readback/poll.ts`
- `src/lib/readback/changes.ts`

## Notes

- Default interval 15 minutes, plus a "Check now" button.
- Ignore Keel's own commits.
- Also show acceptance scenario results per requirement from CI when available.
- As built:
  - Check (`src/lib/readback/poll.ts`): fetches the pushed branch and reads the commits since Keel's last push that touch `docs/` or `tasks/`.
    - Keel's own commits (author Keel, or a "Keel: " subject) are ignored.
    - Each changed document becomes one pending change, with the agent's latest commit and every commit message.
    - A file that already matches Keel's version is left out.
  - Schedule: every `KEEL_READBACK_MINUTES` (default 15; 0 turns it off), started once in `src/instrumentation.ts`, one check at a time. "Check now" on the Handoff page checks at once.
  - Review (`src/lib/readback/changes.ts`), on the Handoff page's Read-back card: each change shows its commit, author, date, messages and the line changes against Keel's version.
    - **Accept** saves the agent's text as the document's next version. Keel keeps the header (ID, status, approvals). The reason is "Read back from <commit>: <messages>".
    - A new document the agent added, such as a task with a Keel header, is taken as it is.
    - **Dismiss** hides it.
    - Either way that commit is handled for that file; a later commit to the file shows it again.
  - State (`readback` in project.md: last check, pending and handled changes) is in git.
  - The stage bar's Handoff step says "Pushed · N changes to review", and the Projects page shows the repository status and the number of changes to review.
- Fixed after the final verification: the Read-back card shows the real schedule (`KEEL_READBACK_MINUTES`), or that automatic checks are off.
