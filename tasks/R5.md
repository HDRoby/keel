# R5 · Documents written and committed in the folder

## Goal

Write documents to `docs/`, `tasks/` and `features/` of the project folder and commit only Keel's own paths.

## Scenarios that prove it

- `features/project-folder.feature` › Keel commits only its own files

## Files that are likely to change

- `src/lib/store/git.ts`: `commitFiles(root, paths, message)` uses a pathspec (`git commit --only -- <paths>` after `git add -- <paths>`) so the user's staged files stay staged and out of Keel's commit. Author `Keel <keel@localhost>`, subject prefixed `Keel: `.
- `src/lib/store/documents.ts`: paths from `config.yml` `paths`.

## Rules

- Refuse to commit during a merge, rebase or cherry-pick (`.git/MERGE_HEAD`, `rebase-merge`, `rebase-apply`, `CHERRY_PICK_HEAD`). Show "Finish the merge in git, then try again" and keep the change unsaved.
- Before writing a document, compare the working copy with Keel's last version. If it differs (someone edited it), do not overwrite: show it in read-back first.
- Commit to the current branch. A detached HEAD is refused with a message.
- `config.yml` commit mode `auto` (default) or `off`. With `off`, Keel writes files but does not commit; versions then come from Keel's own record in `.keel/` history. Implement `auto` only in this task; `off` can be a follow-up if it adds risk.

## As built

- `src/lib/store/git.ts`:
  - `commitFiles` stages only the given paths (`git add -- <paths>`) and commits them with `git commit --only -- <paths>`, so files the user staged stay staged and out of Keel's commit. On a repository with no commit yet, `--only` cannot be used, so the paths are given without it (git commits only those paths anyway).
  - Every Keel commit has author `Keel <keel@localhost>` and a `Keel: ` subject (`keelSubject`), including document versions (`Keel: INT-0001 v2: …`), brainstorm turns, config, mocks and read-back. Reindex already reads both forms.
  - `commitSquashing` folds a brainstorm turn into the last commit only when that commit is Keel's own with the same subject prefix and is not on any remote-tracking branch, so pushed or other people's commits are never amended.
  - `commitBlocker(root)` gives the reason Keel must not commit: a merge (`MERGE_HEAD`), rebase (`rebase-merge`, `rebase-apply`) or cherry-pick (`CHERRY_PICK_HEAD`) in progress, or a detached HEAD ("Finish the merge in git, then try again", and so on). The commit functions throw `RepoBusyError` as a last line of defence.
  - `keelVersionOf(root, path)` is the content of the newest commit by Keel that touched the path.
- **The change stays unsaved:** `createDocument`, `saveDocument`, `updateConfig`, `initialiseProject`, the brainstorm save and the mock saves check `commitBlocker` before writing any file, and return `repo-busy` (or throw before writing). Every form action checks first and shows the reason on the page; the brainstorm API answers 409 with the reason.
- **Edited outside Keel:** `saveDocument` compares the working copy with the version Keel last committed (or HEAD, for a document Keel never committed). If they differ, it refuses with `edited-outside` ("… has changes made outside Keel. Review them on the Handoff page (read-back) first.") and leaves the file alone. Read-back's accept passes `external: true` (R6).
- Commits go to the current branch; a detached HEAD is refused.
- Commit mode: only `auto` is built, as the task allows. `off` and renamed document folders (`config.yml` `paths`) are stored and shown in Settings but not used yet; the folders are `docs/`, `tasks/` and `features/`. Both are follow-ups.
- Tests: `git.test.ts` (only Keel's paths committed while the user's staged file stays staged, each blocking state, Keel's last version, no folding into a pushed commit) and `documents.test.ts` (edited-outside refusal and accept, merge in progress keeps the file unchanged).
- The scenario "Keel commits only its own files" passes: with `src/app.ts` staged, saving the intent makes a commit by Keel with only `docs/intent.md`, and `src/app.ts` is still staged.
