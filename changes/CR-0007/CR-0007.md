# CR-0007: Design as decisions, with options proposed by the assistant

## Why

The Spec's Design section is prose written by the model. The tech stack and other choices are buried in it, with no way to compare options or change one cleanly.

## What changes

1. **Design is a list of decision topics.** The spec template defines the topics (for example Form, Language and framework, Storage, Model access, Testing). The assistant can add a topic when a requirement needs one, and says why ("Added by the assistant for REQ-007").
2. **Options per topic.** The assistant proposes two or three options. Each option shows:
   - a one-line summary, one advantage and one drawback;
   - the requirements it serves;
   - a fit line: which standard or constraint it follows, or which it breaks or conflicts with;
   - "Recommended" on one option, with the reason.
3. **Where the options come from.** The intent's requirements and constraints, the standards chosen for the project, and the code already in the folder. If the folder has code (for example `package.json`), "Keep current: <stack>" is offered first.
4. **Your own option.** Each topic has a field for an option that is not listed. The assistant reviews it against the requirements and standards when the user decides.
5. **Deciding.** The user picks an option, edits the reason, and presses Decide. The choice is saved as a decision record in `docs/decisions/` (decision-record template) with the alternatives considered.
6. **Changing a decision.** "Change" reopens the topic.
   - While the spec is a draft, saving rewrites the same decision record and adds a line "Changed from <old> on <date>".
   - After the spec is approved, the change becomes a change request; a new record supersedes the old one, and both stay in history.
7. **The rest of the spec follows.** "Approach" is assembled from the chosen options. Components, feasibility ratings and flagged concerns are updated from them. For example, choosing "Poll the GitHub API" adds a token-storage concern.
8. **Gate.** Generate plan needs every topic decided, in addition to a Go decision and the scenario coverage from CR-0006 (REQ-005).
