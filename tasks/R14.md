# R14 · Clickable mock prompt and mock sets

## Goal

Hand the spec to an external model as a prompt, take the exported screens back as a versioned mock set, and use it in the gate, the plan and the handoff.

## Scenarios that prove it

- `features/mock-references.feature` (all scenarios)

## Data

- `docs/mocks/set-<n>/` holds the files; `docs/mocks/README.md` lists every set.
- Mock set record (in `.keel/config.yml` or `.keel/mocks.json`): `{ set, specVersion, exported, files: [{ path, kind: 'png' | 'html' | 'link', screen, reqs, matched: 'name' | 'user' }], status: 'current' | 'replaced' }`.
- Out of date is computed: `specVersion < current spec version`.

## Files that are likely to change

- New `src/lib/mocks/prompt.ts`: `mockPrompt(spec, intent, decisions, standards)` returns markdown. Pure function, no model call. Screens come from `inferScreens(spec)`: one per main stage or area named in the requirements and scenarios, with their REQ IDs. Unit tested with the Keel spec.
- New `src/lib/mocks/match.ts`: parse `spec-v<N> · <number> · <screen> · <REQ IDs>.<ext>`; pair PNG and HTML by name; unmatched files are returned for the user to assign.
- `src/lib/mocks/*` (from T7): store sets, write the README, mark sets replaced; keep links, images and PDF as other references.
- `src/lib/gates/*`: mock gate reads `mockGate: recommended | required | off` from `.keel/config.yml` and applies only when the Form decision is a UI form (web app, desktop app, mobile app; not CLI or library).
- `src/lib/generate/plan.ts`: link tasks to screens of the current set (by REQ ID).
- `src/lib/handoff/scaffold.ts`: AGENTS.md section "Visual reference" points to the current set, sources first.
- `src/app/(project)/spec/page.tsx`: Clickable mock tab as in `docs/mocks/source/Spec.dc.html` (status line, prompt pack with Prompt and Screens views, Copy and Download, drop area, matching table, mock sets, other references).
- `src/app/settings/*`: "Clickable mock before the plan" select in This project.

## Notes

- Never send the files to a model. Matching is by file name only.
- Files are checked for type and size (PNG, HTML, PDF; 10 MB each) and HTML is never rendered unsandboxed inside Keel; show it as a download or in a sandboxed iframe.

## As built

- **Prompt:** `src/lib/mocks/prompt.ts`. `mockPrompt(store)` is pure assembly from the project files, with no model call. It includes the problem, the first user, the Form and stack choices, the requirements with their IDs, the screens, the UI standard, the locked and empty states the scenarios describe, the rules, and the export naming `spec-v<N> · <number> · <screen> · <REQ IDs>.png` with the HTML source alongside.
  - `inferScreens` makes one screen per feature file with the requirement IDs its scenarios prove, in requirement order, plus a screen for each requirement no scenario covers.
  - The UI standard is `docs/ui-guide.md` when the project has one, otherwise a neutral design.
- **Matching:** `src/lib/mocks/match.ts` (pure, also used in the browser) parses the export name and pairs PNG and HTML by base name. A name without REQ IDs takes them from the screen with the same name or number and is marked "Check: no REQ in name"; any other name says "Choose a screen".
- **Sets:** `src/lib/mocks/sets.ts`.
  - Files go to `docs/mocks/set-<n>/` (`<number>-<screen>.png|html`; files are checked by content, PNG and HTML only, 10 MB each, 50 MB a set). `docs/mocks/README.md` lists every set and the current set's screens. The record goes in `.keel/mocks.json` (`set`, `specVersion`, `exported`, `link`, `files[]`, `status`). All of it is one Keel commit.
  - A new set replaces the current one. `mockStatus` is missing, stale (made from an earlier spec version) or current.
- **Gate:**
  - `mock_gate` in `.keel/config.yml` (`recommended` by default, `required`, `off`), set in Settings › This project.
  - It applies only when `formHasUi` (the chosen Form option names a web, desktop or mobile app, not a CLI or library).
  - Required locks the plan with "Needs a current clickable mock (…)". Recommended shows a warning on the Plan page. Off does nothing.
- **Downstream:**
  - Generated task files list the current set's screens for their requirements under Notes.
  - The handoff copies `docs/mocks/` and adds a "Visual reference" section to AGENTS.md, HTML sources first.
- **UI:** the Spec's "Clickable mock" tab:
  - a status line against the setting;
  - the prompt pack, with Prompt and "Screens it asks for", Copy prompt, and Download through `/api/mock-prompt`;
  - Attach the result: choose files or paste a link to the live prototype; the matching table is previewed in the browser and a screen is chosen for unmatched files;
  - the mock sets with Current, Out of date or Replaced;
  - Other references (the spec's mock references moved here from the side column).

  The intent keeps its Mock references card. Server action bodies may be up to 52 MB.
- **Differences:**
  - The UI checklist is not generated from the set yet (item 6, "can be").
  - HTML sources are saved and listed, never rendered inside Keel.
- **Tests:** `src/lib/mocks/sets.test.ts` (5) and `features/steps/mock-references.steps.ts` (4 scenarios).
