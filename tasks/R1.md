# R1 · Project folder and .keel store

## Goal

Replace the workspace of many projects with one project folder and its `.keel/` (ADR-0009, ADR-0010).

## Scenarios that prove it

- `features/project-folder.feature` › Initialising creates the .keel folder
- `features/project-folder.feature` › A folder that is not a git repository becomes one

## Files that are likely to change

- `src/lib/store/workspace.ts`: remove `keelHome`, `projectDir`, `listProjectSlugs`, `SLUG`, `createProject`. Add:
  - `projectRoot(env)`: from `KEEL_PROJECT_DIR`, absolute, must exist.
  - `keelDir(root)`, `isInitialised(root)`.
  - `initialiseProject(store, input)`: `git init` if needed, writes `.keel/config.yml`, `.keel/.gitignore` (`cache/`), seeds libraries, commits "Keel: Initialise project".
  - `readProject(root)` from `config.yml` (same zod schema plus `description`, `templates`, `style`, `paths`).
  - `reserveRequirementIds` and `setProjectStandards` keep their behaviour on `config.yml`.
- `src/lib/store/db.ts`: index at `.keel/cache/index.db`.
- `src/lib/store/server-store.ts`: store keyed by project root, not home.
- `src/lib/store/reindex.ts`: one project.
- `src/lib/seed.ts`: seed into `.keel/`.
- `src/lib/templates/library.ts`, `src/lib/skill-files.ts`, `src/lib/handoff/scaffold.ts`, `src/lib/gates/approvals.ts`, `src/lib/generate/*`: read libraries from `keelDir(root)` instead of `store.home`.
- The `Store` type: `home` becomes `root`.

## Notes

- Keep functions taking the root as a parameter so tests use a temporary folder.
- `slug` disappears from function signatures. Use the project id where a label is needed.
- Tests: rewrite `workspace.test.ts` around a temporary git repository.

## As built

- **Store** (`src/lib/store/db.ts`): `Store` is `{ root, index, user, now? }`. The index lives in `.keel/cache/index.db` and holds documents and versions only; the project comes from `config.yml`, and settings are no longer in the index.
- **Workspace** (`src/lib/store/workspace.ts`): `projectRoot(env)` (from `KEEL_PROJECT_DIR`, must be an existing folder), `keelDir`, `isInitialised`, `readConfig`/`writeConfig`/`updateConfig`, `readProject(root)`, `initialiseProject(store, input)`, `reserveRequirementIds(store, n)`, `setProjectStandards(store, refs)`, `fileNameFor(title)`. `keelHome`, `projectDir`, `listProjectSlugs`, `SLUG`, `createProject` and `project.md` are gone. `config.yml` holds id, title, description, author, created, templates per kind, style, standards, paths, commit mode and `next_req`; it is plain YAML (js-yaml, added as a dependency).
- **Initialise** runs `git init` when needed, seeds `.keel/templates`, `.keel/agent-kit`, `.keel/styles` and `.keel/standards`, writes `.keel/.gitignore` (`cache/`) and `config.yml`, and commits only `.keel/` as "Keel: Initialise project". The brainstorm transcript (`.keel/brainstorm/explore.md`) is written in the same commit, so Start is one commit. Before `.keel/` exists, the choices come from a scratch copy of the seed (`previewRoot()` in `src/lib/seed.ts`).
- **Libraries** read from the project's `.keel/`: templates and agent kit in separate folders (design choice E), template usage counts the documents and the brainstorm in this folder. Mock files moved to `.keel/mocks/` with the index `.keel/mocks/references.md` (design choice E); `features/mock-references.feature` now says ".keel/mocks/".
- **Slugs** are gone from every library signature. The scenario file is `features/<title as file name>.feature`.
- **Server store** (`server-store.ts`): keyed by the project root. The index opens on first use (so nothing is written to a folder that is not initialised), reopens when `.keel/cache` was removed, and a new index is rebuilt from git in the background.
- **Interim, replaced later:** settings and keys moved to `settings.json` in the user config folder now (`src/lib/settings/user-dir.ts`), so no key ever lands in the project folder; R2 adds the migration and the key scan. Read-back state, handoff commands and push records moved from `project.md` to `config.yml` (R6, R7, R8 rework them). The routes keep the `/projects/[id]/…` shape with the project id, and `/start` stays as the Initialise form until R4; `/` redirects to Start or to the project.
- **Git writes are serialised per folder** (`git.ts`), so a brainstorm turn and a form save never race for `.git/index.lock` (seen in the scenario run).
- **Scenarios:** the dev server runs with `KEEL_PROJECT_DIR` and `KEEL_USER_DIR` set to fixed temporary folders, and a `Before` hook empties both for every scenario (design choice D). "Initialising creates the .keel folder" and "A folder that is not a git repository becomes one" pass. The other new scenarios are marked fixme with the task that builds them.
- The templates scenario keeps its wording; "used by 1 project" now means this folder's project, and the page says "cannot be removed while this project uses it (1 document)".
