# R10 · Sections with live comments

## Goal

Explore shows the intent template's sections as fields. The assistant reviews all of them together and writes a comment on top of each one, without send buttons.

## Scenarios that prove it

- `features/brainstorm.feature` (all scenarios)

## Data

- Saved in `.keel/brainstorm/<intent id>.json` (committed, like the transcript), one entry per section:
  `{ key, value | rows: [{ id?, text, origin }], origin: 'user' | 'suggested' | 'accepted', cleared?, reviewedHash, comment: { kind: 'challenge' | 'link' | 'suggest' | 'ask' | 'ok', text, linkTo?, rewrite?, dismissed?, applied? }, thread: [{ from: 'user' | 'assistant', text, rewrite?, applied? }] }`.

## Files that are likely to change

- `src/lib/brainstorm/sections.ts`: sections from the template, required flags, progress. Only `user` and `accepted` values count.
- `src/lib/brainstorm/review.ts` (new):
  - `reviewAll(sections, template, style, focus?)`: one model call. The prompt has every section, its value, the template and the style. The answer is validated with zod: `{ comments: { [key]: comment }, suggestions: { [key]: text } }`. Unknown keys are ignored.
  - Suggestions are applied only to empty sections that the user has not cleared.
  - Never writes into a section with `origin: 'user'`.
  - `replyInThread(sections, key, userText)`: same context, answers in that section's thread, then refreshes the other comments.
- `src/lib/brainstorm/scheduler.ts` (new, client side):
  - Triggers: leaving a field with a changed value; a 5-second pause after a meaningful change (finished sentence, or 20 or more characters); Enter in a reply line; opening Explore if anything changed.
  - Fingerprint per section, so an unchanged list is not sent.
  - One call at a time, at most one every 10 seconds, latest change wins. Typing cancels the call in flight (AbortController) and waits for the next pause.
  - Settings (user level): pause length and minimum interval.
- `src/app/(project)/explore/page.tsx`: fields with the comment on top. The focused section shows its comment and thread in full; others show a one-line preview and a "New comment" tag. A status line shows "Reviewing all sections…" or when the list was last reviewed. Apply, Dismiss, Accept and Clear as in the mockup. Remove the chat panel, "Ask me the next question" and "Use a suggested answer".
- `src/lib/generate/intent.ts`: one pure function `intentMarkdown(sections, project, template, style)`, with no model call, used by Draft intent.md. Unaccepted suggestions are left out. New requirement rows get IDs from `reserveRequirementIds`; rows that already have an ID keep it; removed IDs are never reused.
- Requirements section: rows with an ID label ("new" or "suggested" before the first draft), Add requirement, move up, remove, and Accept or Clear for suggested rows. The review can return `addRow` instead of `rewrite` for this section.
- After approval: Explore shows a notice and "Save as change request" instead of Draft intent.md. Saving creates a change request with the section diff and the affected REQ IDs (uses CR-0003 when it exists; until then, a draft intent version marked as a pending change).
- Intent page: a notice that the file is assembled from Explore, a "Change in Explore" link, and headings that follow the template.
- Templates: the intent template declares `Requirements` as a list section (`type: list`). If the shipped template lacks it, publish a new template version. Unaccepted suggestions are left out; empty sections become "_Not written yet._".
- The fake provider returns scripted reviews keyed on section content, so the scenarios stay deterministic.
