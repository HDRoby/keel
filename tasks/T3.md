One ChatProvider interface with streaming, and adapters for Anthropic, OpenAI, Azure OpenAI and OpenAI-compatible endpoints (Ollama). A fake provider for tests.

## Notes

- Keys are stored encrypted (Security baseline v2, rule 2) and never logged.
- Model per task: brainstorm, documents, feasibility review.
- KEEL_PROVIDER=fake selects scripted replies for tests.
- As built: settings live in a `settings` table in keel.db (reindex leaves it alone). Keys are encrypted with AES-256-GCM; the key file is `KEEL_HOME/secret.key` (mode 0600). Settings shows only whether a key is stored.
- `src/lib/providers/registry.ts` picks the adapter for a task. (T4: the brainstorm streams through its own endpoint, `POST /api/projects/[id]/brainstorm`; the interim `/api/chat` endpoint was removed.) With no stored key, the Anthropic SDK falls back to `ANTHROPIC_API_KEY` or an `ant auth login` profile, and the OpenAI SDK to `OPENAI_API_KEY`.
- The Anthropic adapter defaults to `claude-opus-5-5` and turns on server-side refusal fallbacks (`fallbacks: "default"`) for models that support them; a refusal surfaces as a short message, not an error page.
- The fake provider answers "Reply from <provider>: …" so a scenario can tell which provider replied.
