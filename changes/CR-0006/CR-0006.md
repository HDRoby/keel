# CR-0006: Edit acceptance scenarios in the Spec, at least one per requirement

## Why

The Spec shows the acceptance scenarios read-only, grouped by feature. The owner needs to edit them, and to see which requirements have no scenario.

## What changes

1. **Grouped by requirement.** The Acceptance scenarios tab lists every requirement of the spec with its scenarios under it. A requirement with no scenario is marked "No scenario yet". A line at the top says how many requirements are covered.
2. **At least one, as many as needed.** Every requirement needs at least one scenario. More are allowed and encouraged for failure cases and edge cases. There is no upper limit.
3. **Editing.** Each scenario has Edit. In edit mode: the scenario name, each step as a keyword (Given, When, Then, And, But) and text, add step, remove step, delete scenario, Done. "+ Add scenario" under each requirement starts a new one with Given, When and Then rows. The `@REQ-xxx` tag comes from the group, so it cannot be wrong.
4. **Assistant suggestions.** "Suggest a failure case" asks the assistant for a failure scenario for that requirement. It shows as a suggestion (dashed, italic) that counts only when accepted. The assistant never changes a scenario the user wrote.
5. **Gherkin view.** The Gherkin tab shows the `.feature` text built from the accepted scenarios, grouped by feature. A new scenario takes the feature of the requirement's other scenarios, or the requirement's title if it has none.
6. **Gate.** Generate plan needs a Go decision **and at least one accepted scenario for every requirement** (REQ-005).
7. **After approval.** Once the spec is approved, scenario edits become a change request, like other spec edits.
