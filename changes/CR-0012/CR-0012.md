# CR-0012: Startup check before anything else

## Why

Keel depends on a model for comments, drafts and reviews, and on valid settings. Today a missing key, a stopped Ollama or a broken config surfaces only when an action fails halfway. The owner wants Keel to check at startup, warn, and make the user fix it first.

## What changes

1. **The check runs every time Keel starts** (in `npx keel` before the browser opens, and again in the app), and again when the user returns from Settings or presses "Check again". It takes under 2 seconds.
2. **What it checks, in order:**
   1. **Your settings:** `~/.config/keel/settings.json` exists and is valid (schema); the stored keys can be decrypted.
   2. **Model provider:** the chosen provider answers (Ollama: server reachable; cloud: the key is accepted).
   3. **Models for each task:** every task has a model that exists at the provider, and one short test message gets an answer (cached for 10 minutes so restarts stay fast).
   4. **Project config:** if the folder has `.keel/`, `config.yml` is valid: schema, format version, and every template, style and standard it names exists in `.keel/`. (A folder without `.keel/` skips this; Initialise follows.)
3. **All OK:** no page in between; Keel opens the project at its current stage (or Initialise for a new folder). The terminal prints one line: "Startup check: settings OK · Ollama running, 4 models · test message answered".
4. **Something fails: setup mode.**
   - The terminal prints the failing check and "Keel opens in setup mode".
   - The browser opens the **Startup check** page: each check with OK, Needs fixing or Waiting, the reason in plain words, and how to fix it.
   - Until every check passes, only **Startup check** and **Settings** are available (plus **Project setup** when the project config is the problem). Other pages and every action that calls a model are locked, with the reason.
   - First run (no settings at all) says "Set up Keel first" and opens Settings with Ollama preselected (CR-0011).
   - A broken project config is never changed by Keel on its own; the page says which line is wrong and offers Project setup or restoring the file from git.
5. **While running:** if the provider stops answering later, the next model action fails with the same plain message and a link to the Startup check, instead of a raw error.
