# CR-0004: One project per folder, with a .keel folder

## Why

Keel v0.1 keeps every project in `~/.keel/projects/<slug>` and pushes a separate handoff repository. That splits one piece of work over two repositories and adds a Projects page nobody needs. The owner works on one project at a time, in the repository the coding agent builds in.

## What changes

1. **One project per folder.** Keel opens one folder and works only on it. There is no Projects page and no project list.
2. **The folder is the code repository.** The same git repository the coding agent builds code in. Keel's documents (`docs/`, `tasks/`, `features/`) live there next to the code.
3. **Opening Keel.** `npx keel` opens the current folder; `npx keel ./path` opens another one. If the folder does not exist, the command offers to create it. If the folder has no `.keel/`, the browser opens the Initialise screen.
4. **`.keel/` holds all project config and libraries:** config, templates, brainstorm styles, standards, agent kit, brainstorm transcripts and mock files. It is committed with the project. Only `.keel/cache/` is ignored by git.
5. **Secrets and personal settings live outside the project:** API keys, provider connections, model per task and the author's personal library are in the user config folder (`~/.config/keel/`, override with `KEEL_USER_DIR`). Nothing secret is ever written to `.keel/` or anywhere in the project folder.
6. **Handoff writes into the same folder.** No separate repository and no GitHub repository creation. Handoff writes the agent files (AGENTS.md, CLAUDE.md, REVIEW.md, agent kit, standards as skills, failing scenarios, CI). A zip download stays as an option.
7. **Push is optional.** If the folder has a git remote, a Push button runs `git push` with the user's own git credentials. Keel stores no repository token for pushing.
8. **Read-back from local git.** Keel reads the agent's commits and uncommitted edits to `docs/`, `tasks/` and `features/` straight from the folder. No fetch, no polling of GitHub.
9. **Other ideas.** An idea for this project goes on its roadmap or becomes a change request. An unrelated idea gets its own folder and its own Keel run. On the roadmap, "Open as idea" becomes "Start in its own folder", which gives the command to run.
