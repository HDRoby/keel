# R4 · Routes and screens without Projects

## Goal

One project, so no project id in the URL and no Projects page. Screens follow the clickable mockup (CR-0004 version).

## Scenarios that prove it

- `features/project-folder.feature` › Opening a folder without .keel offers to initialise it
- `features/stage-gating.feature` (unchanged scenarios, new URLs)

## Routes

| Before | After |
| --- | --- |
| `/` (Projects list) | `/`: Initialise when the folder has no `.keel/`, otherwise redirect to the current stage |
| `/start` | removed; its form is the Initialise screen at `/` |
| `/projects/[id]/setup` | `/setup` |
| `/projects/[id]/explore`, `intent`, `spec`, `plan`, `handoff`, `trace`, `versions` | `/explore`, `/intent`, `/spec`, `/plan`, `/handoff`, `/trace`, `/versions` |
| `/api/projects/[id]/*` | `/api/*` (brainstorm, handoff, mocks) |
| `/templates`, `/styles`, `/settings` | same paths |

## Files that are likely to change

- Move `src/app/projects/[id]/*` to a route group `src/app/(project)/`. Its layout redirects to `/` when the folder is not initialised.
- Delete `src/app/(workspace)/page.tsx` and `start/` (ask the owner before deleting, or move to `_removed/` if deletion is not allowed).
- `src/app/projects/actions.ts`: drop `createProject` and `deleteProject`; add `initialiseProject`.
- `src/components/Shell`: header shows the project title and its folder path in grey. Nav groups:
  - **Project:** Project setup, Explore, Intent, Spec, Plan, Handoff, Roadmap, Changes.
  - **Library:** Templates, Brainstorm styles, Standards.
  - **Settings**, at the bottom.
- `src/components/StageBar`: no `project` prop; hrefs are top-level.
- Templates, Styles and Standards pages: subtitle "Stored in .keel/templates" (or styles, standards).
- Settings page: two cards. **This project** (`.keel/config.yml`: paths, commit mode, read-back interval). **You, on this computer** (user config folder: providers, keys, model per task, author).
- Not-found page: link to `/`.

## Initialise screen

- Title "Initialise this folder", the folder path, and a note "Keel will create .keel/ here. Nothing else changes until you approve documents."
- Fields: title, description, author (prefilled from git), templates per kind (intent, spec, plan), brainstorm style, standards. The same cards as the old Start page.
- If the folder is not a git repository: "This folder is not a git repository. Keel will run git init."
- If `docs/intent.md` with a Keel header exists: "Keel documents found" with Adopt (R9).
- After the folder card, a "What Keel creates in this folder" section:
  - One short note per choice (the idea, intent template and style, document templates, agent kit, standards), each with how many files it produces.
  - A table of every path Keel will create, with what it is for and when: Now (Initialise), As you approve, or At handoff.
  - Paths that depend on a selection (standards, agent kit, REVIEW.md, mocks) are shown in a different colour, with a colour key. They can be zero to many files.
  - Each folder can be opened and closed, and all folders start closed. A closed folder shows how many files it holds. "Expand all" and "Collapse all" sit in the table header. The table is a reference, not a step.
  - The table updates as the user changes the choices below. A line under it says how many files Initialise writes, all inside `.keel/`.
- Button "Initialise and start brainstorm" goes to `/explore`.

## As built

- **Routes:** stage pages moved from `src/app/projects/[id]/` to the route group `src/app/(project)/` (`/setup`, `/explore`, `/intent`, `/spec`, `/plan`, `/handoff`, `/trace`, `/versions`, plus new `/roadmap` and `/changes`). Its layout redirects to `/` when the folder has no `.keel/`. The actions moved to `src/app/(project)/actions.ts` and no longer take a project field. The API is `/api/brainstorm`, `/api/handoff` and `/api/mocks/[mock]`. The library and settings pages live in `src/app/(keel)/` (`/templates`, `/styles`, `/standards` (new), `/settings`). Deleted as the owner agreed: the Projects page, `/start` and the old group layout.
- **`/`** (`src/app/(keel)/page.tsx`): Initialise when the folder has no `.keel/`, otherwise a redirect to the furthest open stage.
- **Initialise screen:** "Initialise this folder", the folder path, the note that nothing else changes until you approve documents, and "This folder is not a git repository. Keel will run git init." when that applies. Fields: title, description, your name (git config, then Settings), intent template (cards), spec and plan templates (selects), brainstorm style, standards. The choices come from the seed library, because `.keel/` does not exist yet. `?title=` and `?description=` from `npx keel` prefill the form. The button "Initialise and start brainstorm" goes to `/explore`. The spec and plan templates are saved in `config.yml` `templates`.
- **"What Keel creates in this folder"** (`src/components/WhatKeelCreates.tsx`, client component): one note per choice with file counts. Below them, a table of every path with what it is for and when (Now, As you approve, At handoff). Paths that depend on a choice (mocks, REVIEW.md, subagents, standards as skills) are shown in amber, and the cache is shown in grey; a colour key sits above the table. Folders start closed and show how many files they hold; "Expand all" and "Collapse all" sit in the table header. The table follows the form as you type: title → scenario file name, templates, chosen standards. A line under it says how many files Initialise writes, all inside `.keel/`. The "Keel documents found / Adopt" note comes with R9.
- **Shell:** the project title, with the folder path in grey, at the top of the sidebar ("Not initialised" before Initialise). Groups: **Project** (Project setup, Explore, Intent, Spec, Plan, Handoff, Roadmap, Changes, and Traceability, which already existed and is kept), **Library** (Templates, Brainstorm styles, Standards) and **Settings** at the bottom. The Shell now sits in the root layout. Before Initialise the Project group has a single link, Initialise.
- **StageBar** and the components (`DocumentReview`, `MockReferences`, `Conflicts`, `RegenerateForm`, the Explore chat) no longer take a project prop; hrefs are top level.
- **Library pages:** subtitles "Stored in .keel/templates" (agent kit in `.keel/agent-kit`), ".keel/styles" and ".keel/standards". Before Initialise they explain that Keel copies the library into `.keel/` at Initialise. They no longer seed anything themselves, so opening Templates on a folder that is not initialised writes nothing.
- **New pages:** Standards (read-only list with the rules; editing is on the roadmap), Roadmap (renders `docs/roadmap.md` and points unrelated ideas to their own folder with `npx keel ../another-idea`), Changes (lists `docs/changes/`; raising and approving change requests across stages is CR-0003).
- **Settings:** a "This project" card (folder, document folders, commit mode and read-back from `config.yml`, shown read-only with "Change these in that file") and "You, on this computer" (name, model per task, providers, GitHub token), kept in the user config folder.
- **Not found** links to `/` ("Back to Keel").
- The scenario "Opening a folder without .keel offers to initialise it" passes. It checks the heading, the folder path, the paths table and the button, that no link is called Projects, and that `/projects` is a 404. The stage-gating scenarios pass with the new URLs.
