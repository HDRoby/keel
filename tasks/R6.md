# R6 · Read-back from local git

## Goal

Read the agent's changes from the folder instead of fetching a pushed repository (ADR-0012).

## Scenarios that prove it

- `features/read-back.feature` (all scenarios)

## Files that are likely to change

- `src/lib/readback/poll.ts`: rename to `check.ts`. Read `git log <handled>..HEAD -- docs tasks features` and `git status --porcelain -- docs tasks features`. Keep `isKeelCommit` and `pendingFrom`. Remove the fetch, `handoffDir` and token use.
- `src/lib/readback/schedule.ts`: `KEEL_READBACK_SECONDS`, default 60.
- `src/lib/readback/changes.ts`: an uncommitted change has `commit: 'working-tree'` and the label "Uncommitted". Accepting it commits the file as a Keel commit with reason "Read back uncommitted edit".
- `src/lib/readback/ci.ts`: only when the remote is GitHub and a token is set in the user settings.
- Read-back state moves from `project.md` to `.keel/config.yml` `readback`.
- Handoff page: also check on window focus.

## As built

- `src/lib/readback/check.ts` (was `poll.ts`): `checkFolder(store)` reads `git log --reverse <base>..HEAD -- docs tasks features` and `git status --porcelain --untracked-files=all -- docs tasks features` in the project folder. No fetch, no `handoffDir` and no token. `isKeelCommit` and `pendingFrom` are kept. The watched files are the documents Keel keeps (`docs/`, `tasks/`) and scenario files `features/*.feature`, but not the agent's step code. A file that is back to Keel's version is left out. Before anything is reviewed, the base is Keel's "Initialise project" commit, so history from before Keel is not read back.
- **Uncommitted edits** are pending changes with `commit: 'working-tree'`, marked "Uncommitted" on the page. An uncommitted edit on top of agent commits is one change ("… (with an uncommitted edit)"). Accepting it commits the file as a Keel commit with the reason "Read back uncommitted edit".
- **Accept and dismiss in one folder** (`changes.ts`): the agent's text is already in the folder. Accept puts Keel's header back on it and saves it as the next version (`saveDocument` with `external: true`); an approved document goes back to draft (unchanged rule). A new file with a Keel header (a task the agent added) is taken as it is, and a scenario file as the agent left it. Dismiss puts Keel's last version back ("Keel: restore … (read-back dismissed)"). A new file Keel never wrote stays, and its fingerprint is remembered so it does not come back. Both refuse during a merge or rebase (R5).
- **State** (design choice C): `config.yml` `readback` holds what was reviewed (`base` and `handled`), committed on accept or dismiss. When no committed change is waiting, the base moves to HEAD and the list is cleared. The last check (time, pending changes, CI) is volatile in `.keel/cache/readback.json`, so a check never commits.
- `schedule.ts`: `KEEL_READBACK_SECONDS` (default 60, 0 turns it off).
- The Handoff page always shows the read-back card ("Read-back from this folder"), with no push needed. It checks when the window gets focus (`CheckOnFocus` → `POST /api/readback`, refresh when the count changes), as well as on "Check now" and on the schedule. The diff compares Keel's last version with what is in the folder. Settings shows the interval.
- `ci.ts` is used only when `origin` is a GitHub remote (`src/lib/store/remote.ts`: `remoteOf`, `githubRepoOf`, `currentBranch`) and a token is set in the user settings, for the current branch. Otherwise the page says why there are no CI results.
- Tests: `readback.test.ts` covers Keel's own commits being ignored, an agent commit accepted as plan v2 in draft, an uncommitted edit committed as Keel, dismiss restoring Keel's version, a new agent task accepted, a change made and undone, the CI conditions, and the schedule. The three read-back scenarios pass.
- The optional push (`github/push.ts`) still exists until R8; it no longer feeds read-back.
