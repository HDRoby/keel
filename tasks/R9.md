# R9 · Adopt existing documents and import old projects

## Goal

Let a folder that already has Keel documents be initialised without losing them, and bring v0.1 projects from `~/.keel/projects/` into a folder.

## Scenarios that prove it

- `features/project-folder.feature` › Initialising a folder that already has Keel documents adopts them

## Behaviour

- **Adopt:** at Initialise, if `docs/intent.md` (or spec or plan) has a Keel header, Keel reads its project id, title, template and style into `config.yml` and keeps the documents as they are. The next requirement number starts after the highest REQ ID found.
- **Import:** `npm run keel -- import ~/.keel/projects/<slug> --dir <folder>` copies `docs/`, `tasks/`, `features/`, the brainstorm transcripts and mock files into the folder, writes `config.yml` from `project.md`, and commits "Keel: Import <slug>". It never changes the old folder.

## Notes

- Running Keel on its own repository should adopt the existing `docs/` (dogfooding check).

## As built

- `src/lib/store/adopt.ts`:
  - `findKeelDocuments(root)` reads the Keel headers of `docs/intent.md`, `spec.md` and `plan.md`: project id, title, author, the templates per kind (only those the library knows), the brainstorm style, the spec's standards, and the highest REQ ID in the folder.
  - `adoptProject(store, author?)` initialises with these: same "Keel: Initialise project" commit, only `.keel/`, documents untouched, `next_req` after the highest REQ ID. It writes a brainstorm made from the intent's own sections (`sessionFromIntent`), so Explore shows the progress, Project setup works, and nothing is added to the intent twice. It then rebuilds the index from git.
  - `importProject(source, store, legacyHome)` copies `docs/`, `tasks/` and `features/`, `brainstorm.md` → `.keel/brainstorm/explore.md`, `docs/mocks/*` → `.keel/mocks/*` (`README.md` → `references.md`), and the libraries from the old workspace (templates split into `templates/` and `agent-kit/`; styles; standards), or the seed when the old workspace has none. It writes `config.yml` from `project.md` (id, title, author, created, standards, `next_req`, handoff commands) and the brainstorm (description, template, style), and commits "Keel: Import <slug>". The old folder is only read. It refuses a folder that is initialised or already has `docs/`, `tasks/` or `features/`.
- `npm run keel -- import ~/.keel/projects/<slug> --dir <folder>` (`src/cli.ts`).
- Initialise screen: when the folder has Keel documents, a "Keel documents found" card lists them (path, ID, version, status) with your name and **Adopt**, which opens the intent. The scenario passes: the intent shows "INT-0001 v3 · status approved", the file is unchanged, and `config.yml` has `id: PRJ-0042`.
- **Dogfooding on Keel's own repository** (a clone): Adopt found PRJ-0001 with the intent v3, spec v7 and plan v7, the three templates, the Challenger style and the five standards. It made one Keel commit touching only `.keel/` and left the working tree clean; read-back found nothing pending. Two findings, both fixed:
  - Keel's own `docs/decisions/0001-go.md` had no `decision: go` field, so the Go decision was not seen and Plan and Handoff stayed locked. The field was added (the text of the record is unchanged); now every stage is open.
  - Handoff refused, because `tasks/T2.md` and `tasks/T8a.md` mention `{{placeholders}}` on purpose. The unfilled-placeholder check now looks only at files Keel generates, not at documents and scenarios taken as they are.
  - With those fixed, Handoff on Keel's own repository shows its hand-written AGENTS.md, CLAUDE.md, REVIEW.md, subagents, CI and real step definitions as conflicts, kept unless you choose; package.json and the other setup files are kept as yours.
- Tests: `adopt.test.ts` covers finding and adopting (documents untouched, config, next ID, brainstorm from the intent, stages, index) and importing (every copied path, config from `project.md`, one Keel commit, clean status, old folder unchanged, refusals).
