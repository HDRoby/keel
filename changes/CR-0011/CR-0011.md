# CR-0011: Ollama is the default provider, with the local models listed

## Why

The owner wants Keel to work out of the box, privately and for free, on the computer it runs on. Today the default provider is Anthropic (`DEFAULT_CHOICE` in `src/lib/settings/settings.ts`), and the local option is a generic "OpenAI-compatible" entry with no list of models.

## What changes

1. **Ollama first and default.** The provider list is: **Ollama (on this computer)**, Anthropic, OpenAI, Azure OpenAI, Other OpenAI-compatible server. A new install, and any user without saved settings, uses Ollama.
2. **No key for Ollama.** The settings show "Server address" (default `http://localhost:11434`) instead of "API key", with "No API key needed: nothing leaves this computer."
3. **Models on this computer.** When Ollama is selected, Keel reads the server's model list (`GET /api/tags`, details from `POST /api/show`) and shows a table: model, size on disk, parameters, context length, and a "Good for" hint (larger models for spec and plan, small ones for section comments only).
4. **Model per task from that list.** The "Model per task" selects (Section comments, Spec and plan, Feasibility review) offer the local models. Defaults: the largest model for spec, plan and feasibility; a mid-size model for section comments.
5. **Status.** A tag next to the card title: "Running · N models" or "Not running". When Keel cannot reach the server: a warning "Ollama is not running" with how to start it (open the app or `ollama serve`) and the option to pick another provider. "Check again" reloads the list.
6. **No models installed.** If Ollama runs but has no models, show "No models yet" with a suggested `ollama pull <name>` for a model that suits Keel, and keep the stage actions that need a model disabled with that reason.
7. **Other providers** keep working as today (key stored encrypted in `~/.config/keel`, Test connection).
