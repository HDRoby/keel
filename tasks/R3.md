# R3 · `npx keel [path]` command

## Goal

Start Keel on one folder.

## Scenarios that prove it

- `features/project-folder.feature` › Opening a folder without .keel offers to initialise it
- `features/project-folder.feature` › Opening an initialised folder goes to the current stage

## Files that are likely to change

- `bin/keel.mjs`
- `src/cli.ts`

## Behaviour

- `keel [path] [--title "..."] [--description "..."] [--port N] [--no-open]`. `path` defaults to the current folder.
- If `path` does not exist: ask "Create folder <path>? (Y/n)". On no, exit 1. Non-interactive: exit 1 with a message, unless `--create`.
- Resolve to an absolute path and start Next.js with `KEEL_PROJECT_DIR=<path>` and `cwd` = Keel's install folder.
- Port: `--port`, else the first free port from 3000. Print `Keel for <path>: http://127.0.0.1:<port>`.
- Run lock: `.keel/cache/run.json` holds pid and port (only once `.keel/` exists). If that pid is alive, open its URL and exit 0.
- `--title` and `--description` prefill the Initialise screen (passed as query parameters).
- `src/cli.ts` commands: `reindex` (current folder) and `import` (R9). Both take `--dir`, default the current folder.

## Notes

- Bind to `127.0.0.1` only, as today.

## As built

- `bin/keel.mjs`: `keel [path] [--title "..."] [--description "..."] [--port N] [--no-open] [--create] [--dry-run] [--help]`. The path defaults to the current folder and is resolved to an absolute path.
  - A missing folder: with a terminal it asks "Create folder <path>? (Y/n)"; without one it exits 1 with "… does not exist. Run with --create to create it."; `--create` creates it without asking.
  - Port: `--port` (exit 1 if it is in use), else the first free port from 3000, checked on 127.0.0.1. The server binds to 127.0.0.1 only. It prints `Keel for <path>: http://127.0.0.1:<port>`.
  - Next.js runs from Keel's install folder (`next start` when a build exists, else `next dev`) with `KEEL_PROJECT_DIR=<path>`.
  - Run lock `.keel/cache/run.json` (pid, port, started): written once `.keel/` exists (checked every 2 s, so a folder initialised during the run gets it too) and removed on exit. If the recorded pid is alive, the command opens that URL and exits 0.
  - `--title` and `--description` are passed as query parameters; `/` forwards them to the Initialise form (still `/start` until R4), which prefills Title and the idea.
  - `--dry-run` prints what would happen as JSON and exits; the unit tests use it, so no server starts in the test run.
- `src/cli.ts`: `reindex` takes `--dir` (default the current folder). `import` comes in R9.
- `/` now goes to the furthest open stage of an initialised folder (the scenario "Opening an initialised folder goes to the current stage" passes), or to Initialise when there is no `.keel/`.
- Tests: `src/cli/keel-command.test.ts` runs the command for the folder and port, the prefill URL, missing folders, the run lock (live and stale pid) and bad options.
- Checked by hand: `node bin/keel.mjs <new folder> --create --no-open` started Keel on port 3000 and wrote nothing until Initialise. Initialise in the browser made one commit, "Keel: Initialise project" by Keel, and wrote `run.json`. A second `--dry-run` reported the running Keel.
- The settings migration now logs why it could not run (names only). In the sandboxed check, `~/.config/keel` could not be created, and the log line showed that.
- Note: `next dev` allows one dev server per install folder, so from a source checkout two folders cannot run at once. A built install (`npm run build`, then `next start`) has no such limit (design choice D).
- README: "Run on a folder", running the dev server with `KEEL_PROJECT_DIR`, and reindex with `--dir`.
