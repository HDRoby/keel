# R13 · Every screen looks like the mockup

## Goal

One set of tokens and components, used by every page, so all screens match `docs/mocks/source/`.

## Steps (small, one commit each)

1. **Tokens.** Replace the variables in `src/app/globals.css` with `docs/ui/keel-tokens.css` (same names as the mock sources' `var(--…)`). Fix every difference listed in `docs/ui/README.md` (body 14/20, colours, radii, button weight 400). Body text 14/20. Remove global element styles that fight the components (h1 to h3 margins, button styles) once the components exist.
2. **Components.** Create `src/components/ui/` with: Card, PageHeader, StageBar (move it here), Button, LinkButton, Tag, Notice, StatusLine, ProgressLine, Field, SectionField, Comment, OptionCard, ListRows, ScenarioCard, Tabs, Segmented, FileTree, CodeBlock, DataTable, MetaGrid. Each has props for the states in the guide. CSS modules per component; no hex colours, only variables. Take the values from `docs/ui/keel-components.css` (layout, spacing, borders, type) and `docs/ui/states.md` (hover, focus, disabled). Icons: Material Symbols Outlined, self-hosted (`material-symbols` package).
3. **Gallery.** `src/app/dev/ui/page.tsx`, shown only when `NODE_ENV !== 'production'`, renders every component in every state with the sample data from the mock sources. Compare it with `docs/ui/components.html`; a Playwright check can screenshot both at the same size.
4. **Shell.** `src/components/Shell.tsx` to the guide: side menu groups (Project · title, Library (.keel), Settings), active item style, header bar with title and "Keel · <folder path>".
5. **Screens**, one commit each, in this order: Initialise, Project setup, Explore, Intent, Spec, Plan, Handoff, Settings, Templates, Brainstorm styles, Standards, Roadmap, not-found. For each:
   - read `docs/mocks/source/<Screen>.dc.html` and the checklist row in the guide;
   - rebuild the page from the components; keep behaviour and tests as they are;
   - remove page-level inline styles and one-off CSS.
6. **Guard rails.**
   - ESLint: forbid the `style` prop in `src/app/**` (for example `react/forbid-dom-props` with `style`, or a small custom rule).
   - Test `src/ui.guard.test.ts`: fails on `#[0-9a-f]{3,8}` outside `src/app/globals.css` in `src/**/*.css` and `src/**/*.tsx`.
   - Script `npm run ui:shots`: Playwright opens every route against a fixture project (the Keel sample data from the mocks), 1440 × 900, full page, saves `test-results/ui/<route>.png`. Not part of `verify`; run it before reporting.

### Where a screen differs from its mock, and why

These need behaviour Keel does not have yet, so the look stops where the behaviour does:

- **Initialise:**
  - The four opening cases are CR-0010.
  - The agent kit choice and the template choices for agent instructions, roadmap, tests and decision records are not chosen at initialisation today.
  - The labels stay "Title", "Description" and "Your name", which the scenarios use.
- **Spec:**
  - Clickable mock is CR-0009.
  - Flagged concerns stays a section of the document rather than its own tab.
  - The feasibility review is the spec's text section, not rated rows.
- **Intent:** mock references stay a card in the side column rather than a tab. The mock-reference scenario attaches from `/intent` directly.
- **Plan:** the version list, diff and impact are on the Versions page (rebuilt to the same layout), not on the Plan page.
- **Roadmap:** moving items between columns, Start work, Add idea and Suggestions are not built. The board shows the file's columns, and each Next item can raise a change request.
- **Templates:** New per group, the "Back to <origin>" bar, and the metadata and section tables are not built. The detail shows versions, usage, removal and the editor.
- **Settings:** the mock's single "Save settings" and one provider picker would change how settings are saved. Keel keeps a form per setting and a panel per provider, laid out in the mock's two sections. Project settings are read-only, as before.
- **Startup check** is CR-0012.
