# T1 · Document store: markdown with YAML front matter in git

## Goal

Create, read and version project documents as markdown files with YAML front matter inside a git repository per project, and keep a SQLite index in step.

## Scenarios that prove it

- `features/intent-document.feature` › The intent carries its metadata (@REQ-002)

## Files that are likely to change

- `src/lib/store/workspace.ts`
- `src/lib/store/documents.ts`
- `src/lib/store/git.ts`
- `src/lib/store/db.ts`
- `src/lib/store/*.test.ts`

## Notes

- Workspace folder from KEEL_HOME (default ~/.keel). Project slug folders under projects/.
- Use gray-matter for front matter; never put secrets in documents.
- Every save is a git commit with a message that includes the document id and version.
- The SQLite index can be rebuilt from git (`npm run keel -- reindex`).
- As built: project metadata (id, title, author, created) lives in `project.md` at the root of each project repository, so reindex can rebuild projects too. Rebuild logic is in `src/lib/store/reindex.ts`. Commit messages are `<id> v<version>: <reason>`; reindex reads versions back from them.
- `bin/keel.mjs` now starts the Next.js server and opens the browser (its TODO was marked T1).
