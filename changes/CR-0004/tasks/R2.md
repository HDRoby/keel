# R2 · User config folder for settings and secrets

## Goal

Move provider settings, keys and the model per task out of `keel.db` into the user config folder (ADR-0011).

## Scenarios that prove it

- `features/project-folder.feature` › Keel never writes keys into the project folder

## Files that are likely to change

- New `src/lib/settings/user-dir.ts`: `userDir(env)` = `KEEL_USER_DIR` or `$XDG_CONFIG_HOME/keel` or `~/.config/keel`. Created with mode 0700.
- `src/lib/settings/secrets.ts`: key file in `userDir()`.
- `src/lib/settings/settings.ts`: read and write `settings.json` (atomic write, mode 0600) instead of `store.index.getSetting`.
- `src/app/settings/*` (moved by R4).

## Notes

- One-off migration: if `~/.keel/keel.db` and `~/.keel/secret.key` exist and `settings.json` does not, copy the provider settings across, decrypting with the old key and encrypting with the new one. Log "Moved settings from ~/.keel" without values.
- Add a unit test that writes a key through Settings and then scans every file under the project folder (including `.keel/`) for the key and for `sk-` and `ghp_` patterns.
- Author default: `git config user.name`, then the value in `settings.json`.
