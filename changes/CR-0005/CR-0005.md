# CR-0005: Explore: template sections with live comments from the assistant

## Why

Today Explore is a chat that asks one question at a time, with a "Next step" checklist on the side. The owner wants the template to drive the page: the user fills in the sections, and the assistant keeps commenting on all of them, one topic at a time for the user but with the whole list as context.

## What changes

1. **Sections are the page.** Explore shows one field per section of the chosen intent template, centred, with required and optional sections marked and a progress line. There is no separate chat and no "Brainstorm" button.
2. **A comment on top of every section.** The assistant reads all sections, the template and the style, and writes a comment above each section. A comment is one of:
   - **Challenge:** questions the section and says why.
   - **Links sections:** points out where this section conflicts with or depends on another one (cross-reference).
   - **Suggestion** or **Question:** for empty or thin sections.
   - **Looks good.**
3. **When the assistant is called** (no send buttons):
   - When the user leaves a section whose text changed since the last review.
   - After 5 seconds without typing, if the text changed meaningfully (a finished sentence, or 20 or more characters).
   - When the user presses Enter in a comment's reply line.
   - Once when Explore opens, if anything changed since the last review.
4. **One call reviews the whole list** and returns a comment per section. Rules:
   - Skip the call when no section changed since the last review (fingerprint per section).
   - At most one call at a time, and at most one every 10 seconds; the latest change wins.
   - If the user types during a call, cancel it and retry at the next pause.
5. **One topic at a time.** The focused section shows its comment and reply thread in full. Other sections show a one-line preview. A section whose comment changed while the user was elsewhere gets a "New comment" tag. A status line says when the list was last reviewed, or "Reviewing all sections…".
6. **Reply under a comment.** A reply line under each comment, sent with Enter. The assistant answers in that section's thread, with the whole list as context.
7. **The assistant never rewrites the user's text on its own.**
   - It may fill an **empty** section as a suggestion (shown in italics). A suggestion does not count towards the gate until the user accepts it; Clear removes it, and the assistant does not refill a section the user cleared.
   - It offers rewrites inside comments. **Apply** puts the text in the field (for a cross-reference, "Apply to <section>"); Dismiss hides it.
8. **Everything stays editable.** Editing a field at any time is the main action.
9. **Requirements is a section in Explore**, required, with one row per requirement. Rows can be added, edited, moved up and removed.
   - The assistant comments on it like any other section, for example when **Desired outcome** promises something no requirement covers, or a requirement conflicts with **Scope**. It can offer a new row ("Add as requirement").
   - When the list is empty and **Desired outcome** has text, the assistant proposes rows as suggestions; each one counts only when accepted.
   - IDs (REQ-001…) are given when the intent is drafted, shown next to the row afterwards, and never change or get reused. New rows show "new" until the next draft.
10. **intent.md is assembled, not generated.** Draft intent.md puts the sections into the intent template exactly as written, with no model call. Requirements get their IDs at that moment.
11. **The Intent page is for review and approval.** It says the file is assembled from Explore and links to "Change in Explore".
   - While the intent is a draft, editing in Explore and drafting again makes a new draft version.
   - Once it is approved, Explore shows a notice and its main button becomes **Save as change request**: the edits become a change request, so later documents see the impact by requirement ID (REQ-005).
12. **Removed:** the chat panel, "Ask me the next question" and "Use a suggested answer".
13. **Gate:** Draft intent.md is enabled when every required section, including Requirements, has text the user wrote or accepted (REQ-005).
