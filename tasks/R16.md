# R16 · Ollama as the default provider

## Goal

Keel works with the models on this computer by default and shows which ones are there.

## Scenarios that prove it

- The scenarios added to `features/providers.feature` from `features/providers-ollama.feature`.

## Files that are likely to change

- `src/lib/providers/types.ts`: add `ollama` to `PROVIDER_IDS`; order the list Ollama, Anthropic, OpenAI, Azure, compatible.
- New `src/lib/providers/ollama.ts`:
  - chat through the existing OpenAI-compatible adapter at `<base>/v1`;
  - `listModels(base)`: `GET <base>/api/tags`, then `POST <base>/api/show` per model for parameter size and context length; 2-second timeout; returns `{ name, sizeBytes, parameters, contextLength }[]`;
  - `status(base)`: `running` | `not-running` | `no-models`.
- `src/lib/settings/settings.ts`: `DEFAULT_CHOICE` becomes Ollama with the best available local model; a pure function `defaultModels(models)` picks the largest for spec, plan and feasibility and a mid-size one (3B to 14B) for section comments. Ollama needs no key; the stored config has only `baseUrl` (default `http://localhost:11434`).
- `src/app/settings/*`: provider card as in `docs/mocks/source/Settings.dc.html` (status tag, server address, model table, Check again, not-running notice); model-per-task selects list the local models.
- Gates and stage pages: when the chosen provider is not reachable or has no models, actions that call a model are disabled with the reason and a link to Settings.
- Fake provider for tests: `KEEL_PROVIDER=fake` keeps working; add a fake Ollama server (a tiny HTTP stub) for the model-list scenarios.

## Notes

- Never call Ollama from the browser directly; the server calls it, so the same rules apply as for other providers.
- Keep `DEFAULT_COMPATIBLE_BASE_URL` for "Other OpenAI-compatible server".

## Notes for this build (2026-11-22)

- CR-0003 ran before CR-0006 to CR-0011, so this change is spec v14 and plan v15 (the change request says v13 and v14).

## As built

- **Provider:** `ollama` is first in `PROVIDERS` ("Ollama (on this computer)"); the compatible entry is now "Other OpenAI-compatible server". `src/lib/providers/ollama.ts`:
  - chat through the OpenAI-compatible adapter at `<server>/v1`, with no key;
  - `listModels` reads `/api/tags`, then `/api/show` per model for parameters and context length, with a 2-second timeout;
  - `ollamaStatus` returns running, no-models or not-running;
  - `defaultModels` picks the largest model for spec, plan and feasibility, and the largest from 3B to 14B for section comments (else the smallest), skipping embedding models;
  - `goodFor` gives the hint shown in the table.
- **Defaults:** `DEFAULT_CHOICE` is Ollama with no fixed model. `src/lib/providers/local.ts` `effectiveChoice` gives the saved choice or Ollama with the default local model, and `providerForTask` is now async and uses it. `modelAvailability` says why a task cannot call a model (Ollama not running, or no models with an `ollama pull` suggestion). Other providers keep working as before.
- **Task names:** Section comments, Spec and plan, Feasibility review (the task ids are unchanged).
- **Settings:**
  - The Ollama card has a status tag ("Running · N models", "No models yet", "Not running"), the warning with how to start Ollama, the model table (model, size on disk, parameters, context, good for), the server address, and Check again.
  - Model per task offers the local models (a datalist on the model field) and shows the effective default.
  - The other providers are a separate card.
- **Unavailable:** Explore shows a note when section comments have no model. Generate spec, Generate plan and Regenerate are disabled with the reason and a link to Settings.
- **Tests:**
  - `KEEL_PROVIDER=fake` reports a running Ollama with two fake models unless a server address is saved. The scenarios save the address of a small HTTP stub (`features/steps/providers.steps.ts`), or of a closed port for "not running".
  - Unit tests in `src/lib/providers/ollama.test.ts` (4).
- **Checked against the Ollama on the build machine:** Settings listed its 5 models with sizes, parameters and context, and defaulted the tasks to the largest chat model.
