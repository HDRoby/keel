# R20 · Publish as keel-sdlc, runnable with one command

## Goal

Remove SQLite, then publish: `npx keel-sdlc [path]` starts a pre-built Keel on a folder, with nothing to clone, install or build; the command is `keel`.

## Scenarios that prove it

- CI job `package-smoke` (macOS, Linux, Windows): pack, install into an empty folder, run `keel --version`, `keel --dry-run`, and start `keel --no-open` on a new folder until the first page answers.
- Existing acceptance scenarios still pass against the standalone server, with the design-decisions storage example renamed (no SQLite).
- A unit test fails if any dependency in the production tree has native code (`binding.gyp`, `.node` files).

## Data

- `package.json`: `name: keel-sdlc`, `private: false`, `bin: { keel: bin/keel.mjs }`, `files: ["bin/", "dist/", ".next/standalone/", ".next/static/", "seed/", "public/", "README.md", "LICENSE"]`, `engines.node: ">=20"`, `repository`, `keywords`, `license`.
- Scripts: `build` (next build, then `scripts/copy-standalone.mjs` copies `.next/static` and `public` into `.next/standalone`), `build:cli` (compile `src/cli.ts`, now only `import`, to `dist/cli.mjs`), `prepack` (build and build:cli), `smoke` (`scripts/smoke.mjs`).

## As built

- **No SQLite.** `Store` is `{ root, user, now? }` in `src/lib/store/store.ts`; `serverStore()` opens nothing. Versions come from commit messages (`src/lib/versions/commits.ts`, `versionFromCommit`). Removed: `db.ts`, `reindex.ts`, `settings/migrate.ts` and their tests, the `reindex` command, `better-sqlite3`. The storage example is now "Markdown files in git" / "A single database file"; `.keel/cache/` holds `run.json` only.
- **Standalone build.** `next.config.mjs`: `output: 'standalone'`, `outputFileTracingRoot` pinned to the repository, the seed traced in, `sharp` traced out and `images.unoptimized` (one logo; no native image library). Keel reads files from folders it is given, so the trace pulls in the whole repository (docs, changes, `.git`) through the instrumentation entry, which route excludes do not cover; `scripts/copy-standalone.mjs` therefore keeps only `server.js`, `package.json`, `.next`, `node_modules`, `seed` and `public` (37 MB), then adds `.next/static`, `public` and `seed`.
- **The keel command** (`bin/keel.mjs`): `serverMode()` is `standalone` when `.next/standalone/server.js` exists, else `dev` (a clone without a build). It sets `HOSTNAME=127.0.0.1`, `PORT`, `KEEL_PROJECT_DIR`, and `KEEL_HOME_DIR`/`KEEL_SEED` from the install folder (`installEnv`), so `seedDir()` finds the seed from any folder. `--version` (and `-v`) prints the package version. `keel import …` runs `dist/cli.mjs` (bundled by `scripts/build-cli.mjs` with esbuild, a new dev dependency) or `src/cli.ts` with tsx in a clone. `npm start` runs `bin/keel.mjs`.
- **Package.** `keel-sdlc`, MIT (`LICENSE`), `bin.keel`, `files` as listed above, `engines.node >=20`, repository, keywords, `prepack` (build and build:cli), `smoke`. All libraries are dev dependencies: the standalone build carries what the server needs (Turbopack bundles the libraries into its chunks), so `npx keel-sdlc` installs one package, with nothing native and nothing per platform. `npm pack`: 15.3 MB, 40.9 MB unpacked.
- **Tests.** `src/package.guard.test.ts` fails on `binding.gyp`, `.node` or `gypfile` in the production dependency tree or the standalone `node_modules`, and shows that `next` as a runtime dependency would fail it. `scripts/smoke.mjs` installs the `.tgz` into an empty folder with a temporary user folder, checks `keel --version`, `keel --dry-run` (mode `standalone`), starts `keel --no-open` on a new folder until the first page answers, and checks the folder was not written to. `KEEL_BDD_SERVER=standalone npm run test:bdd` runs the 65 scenarios against the standalone server: all pass.
- **CI.** `package-smoke` in `ci.yml` on Ubuntu, macOS and Windows: `npm ci`, `npm pack`, `npm run smoke`. `release.yml` runs only on `v*` tags: checks the tag matches `package.json`, verify, pack, smoke, then publishes the tested tarball with provenance using the `NPM_TOKEN` secret (environment `npm`). No tag was created and nothing was published.
- Found, not changed (behaviour beyond this change): `keel import` fails when the v0.1 project has an empty `tasks/` or `features/` folder; the copied empty folder is passed to the commit.
