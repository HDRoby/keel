# R16 · Ollama as the default provider

## Goal

Keel works with the models on this computer by default and shows which ones are there.

## Scenarios that prove it

- The scenarios added to `features/providers.feature` from `features/providers-ollama.feature`.

## Files that are likely to change

- `src/lib/providers/types.ts`: add `ollama` to `PROVIDER_IDS`; order the list Ollama, Anthropic, OpenAI, Azure, compatible.
- New `src/lib/providers/ollama.ts`:
  - chat through the existing OpenAI-compatible adapter at `<base>/v1`;
  - `listModels(base)`: `GET <base>/api/tags`, then `POST <base>/api/show` per model for parameter size and context length; 2-second timeout; returns `{ name, sizeBytes, parameters, contextLength }[]`;
  - `status(base)`: `running` | `not-running` | `no-models`.
- `src/lib/settings/settings.ts`: `DEFAULT_CHOICE` becomes Ollama with the best available local model; a pure function `defaultModels(models)` picks the largest for spec, plan and feasibility and a mid-size one (3B to 14B) for section comments. Ollama needs no key; the stored config has only `baseUrl` (default `http://localhost:11434`).
- `src/app/settings/*`: provider card as in `docs/mocks/source/Settings.dc.html` (status tag, server address, model table, Check again, not-running notice); model-per-task selects list the local models.
- Gates and stage pages: when the chosen provider is not reachable or has no models, actions that call a model are disabled with the reason and a link to Settings.
- Fake provider for tests: `KEEL_PROVIDER=fake` keeps working; add a fake Ollama server (a tiny HTTP stub) for the model-list scenarios.

## Notes

- Never call Ollama from the browser directly; the server calls it, so the same rules apply as for other providers.
- Keep `DEFAULT_COMPATIBLE_BASE_URL` for "Other OpenAI-compatible server".
