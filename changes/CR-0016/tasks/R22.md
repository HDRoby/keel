# R22 · Discuss a change

## Goal

A chat with the assistant about a change, grounded in Keel's documents, that ends in a checked proposal; the user's Agree writes the change request package and keeps the discussion with it.

## Scenarios that prove it

- `features/discuss-a-change.feature` (all scenarios).
- Unit tests: `proposal.test.ts` (schema, extraction of the fenced block, checks), `context.test.ts` (sources, names-only code map, sections pulled by ID, budget and summary), `discussion-file.test.ts` (write, read, move on Agree, park), `keys.test.ts` (key patterns held, never written).

## Data

- Discussion file `.keel/discussions/DSC-NNNN.md` from `discussion@1`. Front matter: `id`, `title`, `status: open | parked | cr`, `cr`, `model`, `style`, `started`, `sources` (the ticked ones), `attachments` (names only). Body: one `### <author> · <date time>` heading per message; summaries under `### Summary of messages 1–N`; proposals as ` ```keel-proposal ` blocks; edits as `### <user> edited the proposal` with the fields changed.
- Proposal (zod, from the last ` ```keel-proposal ` block of a reply):
  ```json
  {
    "title": "string",
    "why": "string",
    "what": ["string"],
    "requirements": [{ "id": "REQ-005 | new", "change": "new | changed | removed", "text": "string" }],
    "impact": [{ "area": "string", "requirements": ["REQ-005 | new"], "what": "string" }],
    "scenarios": [{ "title": "string", "requirement": "REQ-005 | new" }],
    "tasks": [{ "title": "string", "files": ["path (new)"] }],
    "decision": { "title": "string", "alternatives": ["string"] },
    "dependsOn": ["CR-0009"],
    "screens": ["string"]
  }
  ```
- Checks: `{ kind: 'ok' | 'warn' | 'error', text }[]`; an `error` (unknown requirement ID, duplicate of an open change request) disables Agree until edited.
- Change request header: new optional field `discussion: DSC-NNNN`.
- Settings: `ModelTask` gains `'discussion'` (label "Discussion"); `modelChoice` falls back to `documents` when unset.
- Styles: front matter gains `kind: brainstorm | discussion` (missing means brainstorm); config gains `discussion_style` (default `requirements-partner@1`).
