# CR-0008: Make every screen look like the mockup

## Why

The v6 UI pass followed the mockup on some screens only. Pages use different spacing, buttons, tags and card styles, and several screens (Initialise, Explore, Spec design and scenarios, Handoff, Settings) changed in CR-0004 to CR-0007. The owner wants every screen to look like the mockup.

## What changes

1. **One UI guide.** `docs/ui-guide.md` defines the tokens (colour, type, spacing, radius, shadow), the shell, the page patterns, the shared components and a screen checklist. It replaces the "neutral design" note in `docs/mocks/README.md`: same layout, sizes and colours as the mockup, with the system font and no company branding.
2. **Mock sources in the repository.** The mockup's screen files go to `docs/mocks/source/`, so the agent can read exact structure, sizes and copy. The PNGs in `docs/mocks/` are kept; the owner re-exports them from the mockup when convenient.
3. **Shared components.** Every element in the guide's component table exists once in `src/components/ui/` and every page uses them. No page styles its own buttons, cards or tags.
4. **A UI gallery page** at `/dev/ui` (only in development) shows every component in every state, to check them side by side with the mockup.
5. **Screens rebuilt to the checklist.** Each screen in the guide's checklist matches its mock source.
6. **Guard rails.**
   - No inline `style={{…}}` in `src/app/**` (allowed in `src/components/ui/**` for computed values only). An ESLint rule or a test enforces it.
   - Colours only through the CSS variables: a test fails on hex colours outside `globals.css`.
   - A Playwright script saves a screenshot of every route at 1440 px to `test-results/ui/` with a fixture project, for side-by-side review.

No requirement changes: this is a look-and-feel change. Behaviour stays as specified in CR-0004 to CR-0007.
