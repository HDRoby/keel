# R8 · Optional push to the existing remote

## Goal

Replace the GitHub push (T8b) with an optional `git push` to the folder's existing remote.

## Scenarios that prove it

- `features/handoff.feature` › Pushing uses the folder's own remote

## Files that are likely to change

- `src/lib/github/push.ts`: remove repository creation, `handoffDir` and the token in the push URL. Keep `cleanError`.
- New `src/lib/store/remote.ts`: `remoteOf(root)` from `git remote get-url origin`; `push(root)` runs `git push origin HEAD` with the user's own git credentials and environment.
- `src/lib/github/auth.ts`: token only for optional CI results (R6), read from the user settings.
- Handoff page: the Push button shows only when there is a remote: "Push to origin (github.com/owner/repo)". Without a remote: "No remote. Push from your terminal when you are ready."

## Notes

- Never push automatically.

## As built

- `src/lib/github/push.ts` keeps only `cleanError`, which now also hides credentials in URLs. Removed: `pushHandoff`, the working copy (`handoffDir`, `handoffGit`, `gitEnv`), the token in the push, targets, `repositoryOf` and push records. Keel never created repositories, so there was nothing to remove for that.
- `src/lib/store/remote.ts`: `remoteOf(root)` reads `git remote get-url origin` and strips any credentials from the URL. `githubRepoOf` recognises HTTPS and SSH GitHub URLs, and `remoteLabel` shows `github.com/owner/repo` or the URL. `push(root)` runs `git push origin HEAD` with the user's own environment (SSH agent, `GIT_SSH_COMMAND`, credential helpers) and `GIT_TERMINAL_PROMPT=0`, so a missing credential fails with git's own message instead of hanging. It runs plain git because simple-git's environment guard refuses variables such as `GIT_EDITOR`. It refuses on a detached HEAD.
- **Never automatic:** only the Push button calls `push`. The action checks for a merge or rebase first (R5).
- Handoff page: "Push to origin (github.com/owner/repo)" when the folder has `origin`; otherwise "No remote. Push from your terminal when you are ready." A notice confirms "Pushed <branch> to origin (…)".
- `src/lib/github/auth.ts`: the token is only for CI results (R6). Settings now says "GitHub (CI results)", asks for the permission Actions: read only, and says pushing uses your own git credentials.
- The stage bar's Handoff summary says "Written to this folder · …" once Handoff has written its files (`handoff.files`), instead of "Pushed".
- `KEEL_ALLOW_LOCAL_REMOTES` is gone from the code and the BDD config. `.env.example` now lists `KEEL_PROJECT_DIR`, `KEEL_USER_DIR` and `KEEL_READBACK_SECONDS`, and the verifier agent starts the app on temporary folders.
- The settings migration's `KEEL_HOME` check moved into `user-dir.ts` (`migratesLegacy`), so the user config folder helper is the only place in `src` that reads `KEEL_HOME` or the home folder.
- Tests: `github.test.ts` covers the token, `cleanError`, `remoteOf` (credentials stripped, GitHub recognised), a push to a local bare `origin` with only Keel commits, no remote, and a failing push. The scenario "Pushing uses the folder's own remote" passes against a local bare repository.
