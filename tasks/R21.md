# R21 · AI readiness report

## Goal

On demand, for any folder, show how ready it is for coding agents: rule results from a local scan, a model review of the gaps and of the AI files the user ticks, and advice the user can turn into a change request or the baseline plan.

## Scenarios that prove it

- `features/ai-readiness.feature` (all scenarios).
- Unit tests: each rule in `rules.test.ts` against the fixture folders; `grounding.test.ts` (paths and lines outside the scan are dropped; ratings never raised); `secrets.test.ts` (patterns match, values never leave `findSecrets`).

## Data

- `ReadinessRule`: `{ id, area, applies(scan), check(scan, readLocal) => { status: 'pass' | 'fail' | 'na', evidence: Evidence[], params? }, advice: { title, why, impact, effort, action } }`.
- `Evidence`: `{ path: string; line?: number }`. Paths are relative to the folder root.
- Model answer per area (zod schema, rejected and retried once when invalid):
  ```json
  {
    "why": [{ "rule": "AI-03", "text": "..." }],
    "findings": [{ "summary": "...", "evidence": [{ "path": "AGENTS.md", "line": 41 }], "lowersRating": true }],
    "advice": [{ "title": "...", "why": "...", "evidence": [{ "path": "..." }], "impact": "High", "effort": "Small", "action": "add" }]
  }
  ```
  At most 3 findings and 3 advice items per area.
- `ReadinessReport`: `{ id, date, folderCase, model, durationMs, read: string[], areas: { area, rating, summary, evidence, source }[], mapping?: { file, keel, proposal, note }[], advice: { id, title, why, evidence, impact, effort, source, rule?, action }[], modelError? }`. `read` holds names only.
- Advice IDs are stable across runs: the rule ID for rule advice, a hash of area, title and evidence paths for model advice. Ignored IDs are read from the latest report and hidden.

## As built

- **Rules** (`src/lib/readiness/rules.ts`): the sixteen rules of CR-0015 on `readinessScan()`, which adds `scanFacts()` from `src/lib/repo/scan.ts` (all files including `.keel/`, tracked files from `git ls-files --cached --others --exclude-standard`, lockfiles, CI workflows, lint configs, test files, `.gitignore` lines). Commands (AI-03) count only inside code spans and fenced blocks, so prose like "make a scenario" is not a command; package managers (AI-04) skip ones a clause rules out ("never npm or yarn"). In a `new` folder every rule fails and the only advice is "Initialise the folder with Keel"; no model call is made. `.features-gen` is now skipped by the folder walk.
- **Secrets** (`secrets.ts`): `findSecrets` returns `{ path, field? }` only; names (`.env*` except examples, `*.pem`, `*.key`, `id_rsa*`, `credentials*.json`) and key-like fields with a literal value in JSON, YAML or TOML (lockfiles skipped). `mayHoldKeys` also blocks `mcp.json`, `.npmrc` and `.netrc` from being ticked; only `.md`, `.mdc`, `.txt` and rules files can be ticked at all.
- **Mapping** (`mapping.ts`): AGENTS.md Keep; CLAUDE.md, GEMINI.md, Copilot and Windsurf files Point to (Keep when they already point); Cursor rules, Spec Kit and Kiro specs Adopt; `.claude/agents` and `.claude/skills` Keep.
- **Model review** (`review.ts`): one `feasibility` call per area, retried once on an invalid answer, 120 s timeout; names (up to 2,000), the area's rule results, and the ticked files only for Agent instructions, Conventions and Agent tooling (100 KB each, 200 KB in all). The review stops at the first failure and keeps the areas already done; the report then shows "The model review did not finish: <reason>" and standard why texts. **Grounding** (`grounding.ts`) drops findings and advice whose evidence is not in the scan (folders ending in `/` must hold a file) or past the end of the file, keeps why texts only for failed rules, and lets a confirmed finding lower Ready to Partly, never raise.
- **Report** (`report.ts`, `run.ts`): written from `readiness-report@1` (new "Readiness report" select in Templates for new documents, config key `readiness-report`; the seed template before Initialise). The front matter holds the whole report (names, ratings, mapping, advice with choices, hidden IDs, `handed_over`, `change`); never file contents or values. Advice IDs are the rule ID, or `M-` plus a hash of area, title and paths. Saved as `.keel/reports/readiness-YYYY-MM-DD[-N].md` with a Keel commit, or in `<user>/reports/<sha1 of the folder path>/` before Initialise; `startIdea` and `adoptProject` pass those files to `initialiseProject`, so they are in the Initialise commit, then clear them. Compare lists rating changes and advice added or gone.
- **Screen** (`src/app/(keel)/readiness/`): works with and without `.keel/`; setup mode already sends it to the Startup check. `POST /api/readiness` streams one JSON line per step (one run at a time per process). "AI readiness" is in the project menu after Changes and in "This folder"; What Keel found has the optional card. New `ui/ChoiceGroup` (radio buttons with the Segmented look) for Add, Adopt and Ignore.
- **Acting on advice** (`accept.ts`): in a Keel folder, a draft change request (minor, `from_report`), a plan in `.keel/plans/` with one task per accepted item and its prompt and task files from `packageFiles`, committed; the report records the CR. Before Initialise, "Add to the baseline plan" marks the report `handed_over`; Initialise then ticks the rules from agent files (CO-02, AT-02) and Security baseline (SA-01, SA-02), lists what Initialise and handoff already cover (AI-01, AI-02, AT-01, PK-02, PK-03, SA-01, CO-02, AT-02), and `generatePlan` adds the rest as tasks after the planned ones, with a "From the readiness report" section.
- **Fake provider**: answers readiness calls (a why per failed rule; one README advice in Project knowledge); in scenarios it records each readiness request in `KEEL_FAKE_LOG.requests` and reads `KEEL_FAKE_LOG.control.json` (`silent` throws, `bad-path` adds advice based on `docs/does-not-exist.md`).
- **Fixtures**: `existing-ai` gained `.github/copilot-instructions.md` (npm), `.cursor/mcp.json` (`fixture-not-a-key`) and `pnpm-lock.yaml`; `existing` gained a lint-only workflow.
- Run on Keel's own repository: Agent instructions, Project knowledge, Verification, Conventions and Agent tooling Ready; Safety Missing (`.gitignore` lacks `.env*.local`, `*.pem`, `*.key`; the readiness fixture's fake key is flagged).
